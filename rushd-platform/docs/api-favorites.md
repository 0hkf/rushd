# P13 — عقد API المفضلة

التاريخ: 21 أكتوبر 2026. العقد معتمد في [P13/P14](p13-p14-favorites-proposal.md). التنفيذ والاختبارات معزولة؛ **لا ترقية أو تفعيل على قاعدة المشروع الفعلية**. [شرح الكود والتحقق](p13-p14-favorites-verification.md).

## الملكية والسياسة

- لأي حساب مسجل حاليًا: BUYER وADMIN وSELLER القديم. المستخدم من جلسة JWT الحالية؛ لا userId يقبله العقد، ولا وصول إداري لمفضلة الآخرين.
- تضاف ACTIVE/SOLD فقط. DRAFT/INACTIVE أو المفقود يرجع404 حتى للأدمن. لا توسيع لصلاحيات النشر أو قراءة العقارات الخاصة.
- إذا أخفي عقار محفوظ تبقى العلاقة، لكن القراءة تعيد `available:false, property:null` مع معرف العلاقة ووقت الإضافة فقط. لا عنوان أو سعر أو حي أو صورة أو حالة نشر خاصة أو رابط تفاصيل. يحتسب ضمن عدد المفضلة، ويمكن إزالته.
- إعادة النشر تعيد البيانات الحالية في القراءة التالية. الحذف الفعلي مستقبلًا يزيل علاقته عبر FK، دون إضافة حذف عقار أو حساب هنا. لا يمكن سحب بيانات عامة سبق عرضها أو تنزيلها.
- الكتابة تحتاج الكوكيز و`X-XSRF-TOKEN` من عميل المصادقة الموجود. لا تخزين JWT في JavaScript. الردود الشخصية no-store.

## المسارات

| العملية | الطلب | النتيجة |
|---|---|---|
| قائمة | GET `/api/me/favorites?page=0&size=12` | 200 PageResponse |
| حالة دفعة بطاقات | GET `/api/me/favorites/status?propertyIds=15,16` | 200 `{"favoritePropertyIds":["15"]}` |
| حفظ | PUT `/api/me/favorites/{propertyId}`، بلا body | 204 للجديد والموجود |
| إزالة | DELETE `/api/me/favorites/{propertyId}` | 204 للموجود والغائب |

المعرف Long موجب بصيغة عشرية معتادة، دون أس أو كسر أو صفر بادئ. معرفات ردود المفضلة نصوص، بما فيها summary.id؛ لا تغيير عالمي لمعرفات عقود العقار أو المطابقة. Price/area نصوص دقيقة كما في العقد الموجود، دون Number أو تقريب.

page صحيح ≥0، وsize بين1 و100، الافتراضي12. الترتيب ثابت: created_at تنازليًا ثم property_id تنازليًا. status بين1 و100 مدخل في الدفعة قبل إزالة التكرار؛ لا يعيد إلا معرفات يملكها المستخدم وموجودة في الدفعة. لا يكشف وجود العقار أو إتاحته، ولا يكشف قائمة مستخدم آخر.

PUT المكرر لا يغير وقت الإضافة ولا يكرر الصف. DELETE المكرر ناجح؛ إزالة ثم حفظ جديد يعطي وقتًا جديدًا. الملكية لا تتغير بإرسال userId كـquery/body غير معرف في العقد؛ مصدرها authentication فقط. الحفظ والإزالة المتزامنان يتسلسلان بقفل المستخدم، والإضافة تفحص إتاحة العقار تحت قفله؛ القيد الفريد يمنع صفوفًا مكررة كدفاع إضافي.

summary للبطاقة فقط، دون بريد أو هاتف أو اسم/معرف ناشر أو تفاصيل خاصة. primaryImage هو descriptor P10 نفسه أوnull، بتحميل محكوم من الباكند. التفاصيل الكاملة من endpoint العقار الحالي. القائمة قراءة snapshot بمعاملة REPEATABLE_READ؛ الصور تجمع للصفحة العامة فقط، لا لكل بطاقة ولا للعناصر المخفية.

## الأخطاء والتعطيل

-400: معرف/دفعة/صفحات غير صالحة.401: دون جلسة صحيحة عند اجتياز فحص CSRF.403: CSRF مفقود/خاطئ وفق ترتيب Spring الحالي؛ لم نضع استثناء أمنيًا للحصول على401 في كتابة غير صالحة أصلًا.
-404: محاولة حفظ عقار غير متاح؛ DELETE لا يستعمل404 لكشف وجود علاقة لمستخدم آخر.
-503: `rushd.favorites.enabled` معطل. الافتراضيfalse، وبعد فحص المصادقة/CSRF لا يستعلم الخدمة عن المستخدم أو العقار أو جدول المفضلة. لا fallback وهمي في المتصفح.
- الخطأ يستخدم ErrorResponse القائم دون تفاصيل قاعدة أو stack trace. لم تتغير إعدادات JSON العامة أو CORS أو صلاحيات ADMIN أو سياسة CSRF.

## قاعدة البيانات والتفعيل المستقبلي

ملف المراجعة `backend/db/20261021-property-favorites.sql` يضيف `property_favorites(user_id bigint, property_id bigint, created_at timestamptz)`، مفتاحًا مركبًا وفهرس `(user_id,created_at DESC,property_id DESC)`، وFK CASCADE من الحساب والعقار إلى علاقاتهما فقط. لا نسخ عنوان أو سعر أو صورة، ولا تعديل صفوف properties/users.

التطبيق الحالي `ddl-auto=none`؛ لا migration تلقائية. بعد اعتماد تشغيل منفصل ونسخة احتياطية ومراجعة المخطط، تطبق الترقية على البيئة المعتمدة ويضبط `rushd.favorites.enabled=true`. هذا ليس تفويضًا بتنفيذها الآن. لا يكفي ضبط true دون الترقية. الصور إعداد منفصل، ولا يلزم تفعيلها لتعمل المفضلة مع placeholder.

تختبر الترقية فقط عبر `bash backend/scripts/verify-postgres.sh` الذي ينشئ حاوية PostgreSQL محلية مملوكة مؤقتة بـtmpfs، ويرفض أخذ URL قاعدة خارجية. يختبر guard جزئي/replay وPK/FK/CASCADE وعدم تغيير البيانات القديمة، ثم Hibernate validate والحزمة الكاملة، وينظف موارده فقط.
