## الدخول التجريبي المحلي

بموافقة منفصلة، أُنشئ حساب ADMIN جديد مخصص للتطوير المحلي، باسم `Rushd Local Demo Admin` وبريد `local-demo-admin@rushd.test` وكلمة مرور عشوائية. خُزنت كلمة المرور في القاعدة كـBCrypt باستخدام PasswordEncoder القائم؛ لم تُعدّل حسابات موجودة.

بيانات التعبئة محفوظة محليًا في `frontend/.env.development.local` المتجاهل من Git، بصلاحية ملف 600. لا توجد كلمة مرور حقيقية ثابتة في source أو التوثيق. البيانات التجريبية **مرئية لواجهة التطوير عمدًا** لتلبية طلب التعبئة والدخول بضغطة واحدة؛ ليست سرًا آمنًا من مستخدم الواجهة المحلية، ولا تصلح للإنتاج.

الإعدادات المستخدمة، دون قيم سرية في المثال:

```dotenv
VITE_LOCAL_DEMO_ADMIN_ENABLED=true
VITE_LOCAL_DEMO_ADMIN_EMAIL=<local-demo-email>
VITE_LOCAL_DEMO_ADMIN_PASSWORD=<random-local-demo-password>
```

الزر معطل افتراضيًا ويظهر فقط عند اجتماع الشروط:

1. وضع Vite هو development وليس production.
2. اسم مضيف الصفحة loopback بالضبط، وليس اسمًا مشابهًا أو عنوان LAN.
3. عنوان API الفعلي HTTP(S) مطلق على loopback، دون بيانات مستخدم داخل URL. يعاد فحصه لحظة الضغط.
4. التفعيل النصي `true` ووجود البريد وكلمة المرور.

عند الضغط، يعبئ حقلي البريد وكلمة المرور ثم يستدعي AuthContext.login → loginSession المعتاد مع CSRF وHttpOnly cookies. لا endpoint جديد، ولا تعطيل تحقق كلمة المرور أو الصلاحيات، ولا حفظ كلمات المرور أو التوكنات في localStorage/sessionStorage. لا ينتقل إلى `/dashboard` إلا إذا أعاد الخادم دور ADMIN. الدخول العادي وreturnTo لا يتغيران.

للتعطيل، غيّر `VITE_LOCAL_DEMO_ADMIN_ENABLED=false` وأعد تشغيل Vite. تعطيل الزر أو غيابه عن production **لا يعطّل حساب قاعدة البيانات نفسه**: لا تنقل حساب الديمو أو ملف env إلى الإنتاج؛ احذف الحساب التجريبي أو غيّر بياناته بإجراء إداري معتمد قبل نشر القاعدة.
