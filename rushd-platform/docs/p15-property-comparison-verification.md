# P15 — مقارنة عقارين أو ثلاثة

التاريخ: 24 أكتوبر 2026. اكتمل نطاق P15 بعد اعتماد المستخدم السماح بمقارنة أنواع مختلفة. لا تنفيذ P16، ولا تعديل Java أو API أو schema أو بيانات قاعدة المشروع أو صلاحياته، ولا dependency أو مفتاح جديد، ولا commit/merge/push.

## الفحص والقرار

الفرع `feature/property-google-location` وفيه تعديلات سابقة كثيرة محفوظة؛ لا تنسب كلها إلى P15. لم توجد AGENTS.md محلية. فُحصت خطة P15 والمتطلبات، وقراءة Property العامة وعقد الاستجابة ودقة الأرقام ومواصفات الأنواع ومعاني المساحات، والتصفح والتفاصيل وR3 والمفضلة والمصادقة والتنقل والاختبارات.

اعتمد المستخدم مقارنة الأنواع المختلفة مع تمييز غير المنطبق عن المجهول. التنفيذ يعيد استخدام `GET /api/properties/{id}` الحالي، ولا يغير أنواع الطلب أو الاستجابة. لا جدول مقارنة أو تخزين دائم. الإتاحة ACTIVE/SOLD كالتفاصيل العامة القائمة؛ حتى إذا أعاد API عقارًا خاصًا للأدمن لا تدخله هذه المقارنة العامة.

## النتيجة والقواعد

- أزرار إضافة/إزالة في التصفح والتفاصيل ونتائج R3 والمفضلة المتاحة، وصفحة `/compare` ورابط بعدد المختار في التنقل.
- حد أقصى ثلاثة، بلا تكرار؛ ترتيب الأعمدة هو ترتيب الاختيار. يبقى زر إزالة المختار متاحًا عند امتلاء المقارنة. اختيار واحد يعرض دعوة لإضافة آخر، والصفر حالة فارغة واضحة.
- تحفظ **معرفات فقط** في ذاكرة React للتبويب. لا localStorage/sessionStorage ولا حفظ في حساب أو URL مشترك. التنقل الداخلي يحافظ عليها، وإعادة تحميل الموقع أو تغير الحساب/الخروج يمسحها. هذا سلوك مقصود لأول نسخة، وليس مفضلة دائمة.
- تُجلب حتى ثلاثة تفاصيل بالتوازي عند فتح الصفحة والتحديث والعودة إلى النافذة/ظهورها. أثناء التحميل تُزال النتائج السابقة. طلب متأخر أو ملغى لا يعيد بيانات اختيار أزيل أو حساب سابق.
- فشل عمود لا يمنع البقية. 403/404 أو حالة خاصة ينتج خانة غير متاحة دون عنوان أو سعر أو مواصفات أو رابط تفاصيل. أخطاء الشبكة/الخادم أو عقد غير صالح تنتج خطأ عمود وإعادة تحديث، لا نسخة قديمة.
- السعر نص عشري دقيق حتى العرض؛ لا تحويل عبر Number ولا ترتيب «الأرخص» ولا تحويل شهري/سنوي ولا سعر متر أو تقييم استثماري. فترة إيجار قديمة مفقودة تظهر غير محددة بدل افتراض سنوي.
- المساحة الرئيسية تبقى كما هي، ويعرض مصدرها الصريح أو «معلنة غير مصنفة». الأرض وصافي الوحدة وإجمالي الوحدة وإجمالي البناء صفوف منفصلة بالمتر المربع؛ لا نستنتج معنى المساحة القديمة.
- تُعاد قواعد `specificationRows` القائمة لتوزيع الحقول حسب النوع والنطاق وعرض نعم/لا/غير محدد، والصفر الصحيح، والدور الأرضي، والعمر وسنة تقديره دون زيادة العمر تلقائيًا. الحقل خارج النوع «لا ينطبق». إذا كان النطاق التجاري مجهولًا فلا ننسب حقول الوحدة أو المبنى لأحدهما؛ تظهر «النطاق التجاري غير محدد» عند وجود صف يحتاج تحديده.
- الجدول semantic مع caption وscope للصف والعمود، ومنطقة تمرير قابلة للتركيز، وbdi للأرقام داخل RTL. لا تمدد أفقي للمستند في الجوال؛ التمرير داخل الجدول. الهوية والخط والألوان كما هي، مع تقليل فجوات التنقل على التابلت لاستيعاب رابط المقارنة.

## شرح الكود والملفات

### منطق الخدمة

`frontend/src/services/propertyComparison.js`:

- `comparisonId` يقبل معرفًا نصيًا ضمن Java Long أو رقمًا آمنًا قديمًا، ويرفض معرفًا رقميًا فقد دقته أو مسارًا غير صالح. الروابط وطلبات التفاصيل تُبنى من معرف متحقق فقط.
- `changeComparison` عملية نقية للإضافة والإزالة والمسح؛ تعيد حالة جديدة بلا تعديل السابقة، وتحفظ المعرفات فقط وتفرض حد3 وعدم التكرار.
- `readComparisonProperty` يتحقق من تطابق المعرف والإتاحة والنوع والأرقام النصية ودقتها. يختار حقول العرض المطلوبة ولا ينسخ بيانات الناشر أو الحساب. الرد الخاص يعود null، لا مواصفات مخفية.
- `createComparisonLoader` يستخدم request gate الموجود وAbortController، وPromise.all للحفاظ على ترتيب الاختيار مهما اختلف ترتيب الردود. كل عمود يعالج فشله منفردًا، والاستجابة لا تنشر إلا إن كان الطلب ما زال الحالي.
- `comparisonRows` يحول الحقائق إلى صفوف عرض، ويعيد استخدام تعريفات المواصفات وتنسيق الأرقام الموجودين. لا محرك مفاضلة أو score ولا تعديل ترتيب R3.

`ComparisonContext.jsx` يحفظ حالة الاختيارات المشتركة. `comparisonState.js` يفصل السياق وhook عن مكون provider لموافقة Fast Refresh. وُضع provider داخل دورة حياة هوية المفضلة الموجودة، لذلك يعاد إنشاؤه عند تغير الحساب أو استعادة الجلسة دون تغيير المصادقة نفسها.

### العرض والربط

- `pages/PropertyComparison.jsx`: حالات0/1/2/3، تحميل/خطأ/مخفي، تحديث ومسح وإزالة، جدول ومعاني ووحدات، وأحداث العودة للنافذة وتنظيف طلباتها.

## API والحماية

لا endpoint جديد ولا تغيير عقد. مثال مقتطف من GET التفاصيل القائم، وليس بديلًا عن كامل PropertyResponse:

```json
{
  "id": 1,
  "status": "ACTIVE",
  "type": "LAND",
  "listingType": "SALE",
  "rentalPeriod": null,
  "title": "عقار صناعي للاختبار",
  "city": "مكة",
  "district": "النوارية",
  "price": "9007199254740993.01",
  "area": "500.25",
  "specifications": { "primaryAreaSource": "LAND", "landArea": "500.25" }
}
```

القيمة تظهر `9٬007٬199٬254٬740٬993٫01` دون فقد آخر خانتين. الخادم ما زال يفرض إتاحة التفاصيل، وADMIN للكتابة وCSRF وHttpOnly كما كانت؛ مقارنة الواجهة لا تمنح وصولًا جديدًا. لا بيانات ناشر أو tokens في مخزن المقارنة، ولا HTML غير موثوق أو URL خارجي مشتق من الإعلان. تحقق الواجهة ليس بديلًا عن حماية الخادم.

### تجربة المتصفح

بيئة مؤقتة `127.0.0.1:5176/18086` بقاعدة PostgreSQL tmpfs مملوكة، حسابي ADMIN/BUYER صناعيين وخمسة عقارات صناعية مختلطة. إنشاء العقارات وتعديل السعر والإخفاء استعملت API الأدمن العادي. تعديل دور حساب الاختبار حدث داخل القاعدة المؤقتة فقط قبل تسجيل دخوله. الصور معطلة؛ المفضلة مفعلة في المعزول فقط لاختبار تكامل زر المقارنة.

- زائر اختار أرض بيع دقيقة ثم شقة شهريًا ثم عمارة سنويًا. الأعمدة بهذا الترتيب والمبالغ والوحدات منفصلة. امتلاء3 عطّل إضافة الرابع مع إبقاء الإزالة.
- أظهرت المساحات المستقلة، الأرض/صافي الوحدة/إجماليها/البناء، والصفر وfalse والمجهول وغير المنطبق دون تحويل.
- عُدل السعر عبر API من `9007199254740993.01` إلى `.02`، وأُخفيت الشقة مع عنوان خاص؛ بعد تحديث المقارنة ظهر السعر الدقيق الجديد وخانة غير متاحة، دون العنوان الخاص أو القديم أو رابطها أو مواصفاتها.
- إزالة المخفي أعادت المقارنة الثنائية؛ فتح التفاصيل والعودة حافظ على الاختيارات؛ إزالة ثانية أظهرت اختيارًا واحدًا ودعوة لإضافة آخر.
- الدخول لحساب BUYER الصناعي مسح اختيارات الزائر. R1/R3 لطلب LAND/SALE بميزانية نصية دقيقة أعاد نتيجة واحدة؛ إضافة المقارنة لم تغير عددها أو أسبابها. حفظها بالمفضلة أظهر نفس حالة المقارنة في صفحة المفضلة. الخروج مسح الاختيارات، وإعادة تحميل الصفحة مسحت اختيارًا جديدًا كما تنص الواجهة.
- الجوال390×844: عرض المستند390، وداخل الجدول720 ضمن منطقة356؛ لا overflow أفقي للصفحة. تركيز الجدول ثم ArrowLeft حرّك تمريره، وTab وصل لرابط التفاصيل. فُحص التنقل أيضًا بعرضي900 و821 دون تمدد المستند. هذا تحقق يدوي محدد، لا تدقيق وصول شامل أو اختبار قارئ شاشة.
- أُعيد viewport وأُغلقت التبويبات المؤقتة وأُوقفت عمليات الخادم/الواجهة وحاوية الاختبار المملوكة فقط.

## جرّب بنفسك والحدود المتبقية

1. افتح `/properties` واضغط «أضف للمقارنة» لعقارين أو ثلاثة.
2. افتح المقارنة من الشريط أو التنقل؛ راجع السعر ووحدته ومصدر المساحة وصفوف المواصفات.
3. جرّب إضافة رابع، ثم أزل اختيارًا وأضف بديله. افتح التفاصيل وعد إلى المقارنة.
4. اضغط «تحديث المقارنة» لجلب الوضع الحالي. لا تختبر الإخفاء/التعديل على بيانات حقيقية إلا ضمن عمل إداري مقصود؛ تجربة التحقق السابقة كانت معزولة.
5. على الجوال مرر الجدول أفقيًا. إعادة تحميل الموقع تمسح الاختيارات عمدًا.

لا تحديث لحظي/server push ولا snapshot ذرية واحدة للعقارات الثلاثة: كل GET يتحقق عند قراءته، وقد يتغير العقار لاحقًا حتى التحديث التالي. لا روابط مشاركة أو حفظ دائم أو مقارنة سعر متر أو استنتاج أفضلية، ولا AI أو سوق أو صور جديدة. معاينة المتصفح لا تثبت النشر الإنتاجي أو كل المتصفحات والأجهزة. P16 التالية **اعتماد قواعد تقييم عقار مختار** فقط؛ لم تبدأ في هذه الحزمة.
