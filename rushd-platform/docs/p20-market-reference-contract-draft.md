# P20 — تصميم إدارة مراجع السوق للأدمن

11 نوفمبر 2026. **اعتمد صاحب المشروع النطاق والإصدارات والأرشفة ورفع الأصل؛ نُفذ العقد معطّلًا افتراضيًا واختُبر بمعزل.** المرجع: [P19 المعتمد](p19-market-source-review-20261110.md). لا تشمل P20 محرك سعر P21 أو عرض نتيجة سعر P22. تفاصيل العقد المنفذ في [API والتحقق](p20-market-reference-verification.md).

## نتيجة الفحص

- لا يوجد حاليًا نموذج أو جدول أو API أو صفحة لإدارة مراجع السوق. توجد مصادقة cookies وCSRF وADMIN والتحقق العشري الدقيق ومشغل PostgreSQL مؤقت يمكن إعادة استخدامه.
- حقول العقار الحالية ليست تعريفًا لملاحظة صفقة: السعر `numeric(19,2)` والمساحة `numeric(12,2)`. ملاحظة مصدر قد تجمع أكثر من عقار، فلا تنسخ معنى المساحة أو النوع من Property إليها تلقائيًا.
- مصدر P19 المفحوص لا يثبت نوع LAND/APARTMENT… أو معنى المساحة، ويغطي البيع لا الإيجار. لا يستنتج النظام النوع من «سكني»، ولا يغير البيانات أو يحكم على السعر.
- الشجرة الحالية تحتوي تغييرات سابقة كثيرة على `feature/property-google-location`؛ لا تستبدل أو تنسب إلى P20. لم توجد تعليمات AGENTS.md داخل المشروع عند الفحص.

## النطاق المعتمد

1. إدارة مشتركة بين حسابات ADMIN الحالية فقط؛ لا مستخدم عادي أو زائر، ولا تغيير لخصوصية مسودات العقار. يستخرج الخادم هوية منشئ/معدل السجل من الجلسة ولا يقبلها في JSON.
2. مصادر وزارة العدل وصفقات بيع بالريال في مدينة مكة فقط. لا إيجار أو أسعار إعلانات أو استيراد صفوف أو اتصال URL من الباكند أو AI.
3. سجل المصدر يضم اسمًا، رابط دليل رسمي HTTPS، فترة البيانات، تاريخ الحصول عليه، ووصف/مرجع شروط الاستخدام. الأصل مرفق خاص غير قابل للاستبدال، ببصمة SHA-256 محسوبة من البايتات لا مرسلة موثوقة من الواجهة.
4. المراجع تُدخل يدويًا مع رقم الصفقة/موضعها في المصدر. الأصل لا يُعدل لتحسين البيانات. نقص النوع أو معنى المساحة مسموح ومبين كسبب نقص؛ لا يُملأ افتراضيًا.
5. كل تعديل مرجع ينشئ إصدارًا جديدًا بسبب تعديل مطلوب. الحذف أرشفة بسبب مطلوب؛ لا حذف محتوى أصلي أو إصدارات سابقة. اعتمدت هذه السياسة صراحة ولا تُستنتج من كلمة CRUD وحدها.

## التخزين المقترح — منفصل عن Property

| الجدول | الغرض |
|---|---|
| `market_sources` | بيانات إصدار مصدر واحد، ملفه الأصلي الخاص وبصمته، فترة المصدر، جاهزية المرفق، حالة الأرشفة ورقم مراجعة |
| `market_references` | هوية المرجع ومصدره ورقمه الأصلي ورقم إصداره الحالي؛ يمنع تكرار رقم المرجع داخل إصدار المصدر نفسه |
| `market_reference_versions` | إصدارات غير قابلة للتعديل لحقائق المرجع وحالته وسبب التعديل وهوية الأدمن وتاريخ UTC |
| `market_storage_quota` | صف تحكم لحجز حصة الملفات داخل معاملة وقفل؛ لا فحص حجم منفصل معرض لسباق رفعين |

جميع المعرفات الجديدة UUID. المراجعات نصوص أعداد صحيحة دقيقة في JSON. الروابط FK تمنع حذف المصدر المرتبط حذفًا صامتًا. المرفق `bytea` خاص بلا مسار ملف من العميل؛ استعلامات القوائم لا تجلب بايتاته. لا يُنقل ملف المصدر الحقيقي إلى fixtures ولا يُحمّل على قاعدة المشروع.

المصدر يمثل إصدار ملف بعينه. بعد إرفاق الأصل تُقفل بيانات هويته وفترته؛ التصحيح يكون بإنشاء إصدار مصدر جديد ثم أرشفة السابق بسبب، لا تبديل دليل سجل تاريخي. يمكن أرشفة المصدر دون مسح مراجعه؛ تظهر المراجع مرتبطة بمصدر مؤرشف ولا تعتبر جارية. إصدارات نتائج P21 مستقبلًا يجب أن تشير لمعرف إصدار المرجع والمصدر؛ لا توجد نتائج سعرية محفوظة اليوم كي تُعدل أو تُبطل.

## عقد البيانات والتحقق المقترح

- المصدر: اسم 1–150 حرفًا؛ رابط رسمي حتى 1000 حرف، `https` ومضيف `moj.gov.sa` أو `www.moj.gov.sa` فقط، بلا مستخدم/كلمة مرور أو منفذ مخصص أو fragment. الرابط دليل يعرض بأمان ولا يُطلب من الخادم.
- فترة المصدر: بداية ونهاية مطلوبتان، وتاريخ الحصول عليه مطلوب. تواريخ ميلادية صريحة بين 1900 وتاريخ اليوم في الرياض؛ البداية لا تتجاوز النهاية، ولا تقع النهاية بعد الحصول عليه. لا يُخمن تاريخ نشر مجهول.
- وصف شروط الاستخدام/دليلها نص مطلوب حتى 2000 حرف، وملاحظات المصدر حتى 2000. هذا توثيق أدمن وليس تصديقًا آليًا على الترخيص أو الحق في النشر.
- المرجع: رقم مصدر نصي 1–150 حرفًا؛ تاريخ الصفقة مطلوب ويقع داخل فترة المصدر؛ المدينة نص أصلي 1–100 والحي اختياري حتى 150. يقبل نطاق مكة المعتمد فقط دون تحويل المنطقة إلى مدينة أو إعادة كتابة النص الأصلي.
- تصنيف المصدر العام نص اختياري حتى 100؛ نوع العقار التفصيلي ومعنى المساحة اختياريان، ولا يساوي الأول نوع Property تلقائيًا. عند تسجيل معنى/نوع مثبت يلزم نص دليل حتى 2000 حرف يوضح موضعه في مصدر معتمد؛ يبقى ذلك ادعاء أدمن يحتاج مراجعة، لا أهلية تقييم تلقائية.
- السعر الإجمالي للصفقة: مطلوب، `numeric(19,2)`، من `0.01` إلى `99999999999999999.99`. لا سعر متر مشتق أو عملة أخرى.
- مساحة ملاحظة المصدر: اختيارية، `numeric(19,2)`، والمجال الموجب نفسه عند تقديمها؛ ليست تعديلًا لعمود مساحة العقار. تقديم معنى مساحة دون قيمة يرفض. لا يقسم مجموع مساحة صفقة متعددة العقارات على عددها تلقائيًا.
- عدد العقارات: اختياري من 1 إلى 1,000,000 كحد إدخال تقني مقترح، لا دليل إحصائي. المجهول null وليس 1، وتعدد العقارات سبب نقص لمقارنة عقار فردي.
- الطلبات/الاستجابات تحافظ على عشريات BigDecimal، وترجع المبالغ والمساحات كنصوص عشرية. الواجهة تستخدم نصوصًا منذ الإدخال، وتدعم العربية والفارسية والفاصل العربي، دون Number أو تقريب. تجاوز الدقة أو المجال أو أسّ هائل يعيد 400 قبل DB.
- سبب تعديل/أرشفة مطلوب حتى 1000 حرف. تحديث رقم مراجعة قديم يعيد 409 ولا يكتب إصدارًا بديلًا. غياب معلومة يبقى null؛ لا PATCH ملتبس أو مسح حقول غير مرسلة.

## رفع الأصل — الخيار المعتمد

- XLSX فقط، بحد 10 MiB للملف وحصة تجريبية كلية 100 MiB. لا حذف ملف مؤرشف تلقائيًا عند بلوغ الحصة؛ يرفض الرفع ويشرح السبب. الحصة تحفظ في معاملة مقفلة، لا حد ذاكرة لكل خادم.
- يرسل الأصل كطلب ثنائي `application/octet-stream`، لا multipart. بذلك لا يلزم تغيير حدود الصور أو تفعيل تحليل multipart أثناء فحص CSRF.
- فحص مغلف ZIP بحدود عدد عناصر وحجم فك إجمالي، دون استخراج إلى القرص أو قراءة صفوف الخلايا أو تنفيذ شيء. ترفض المسارات المتجاوزة والتشفير والماكرو والروابط الخارجية، مع توثيق أن فحص المغلف ليس ضمان سلامة شاملًا لملف Excel.
- كل محاولة تقرأ تدفقًا محدودًا ولا تقبل بايتات غير محدودة. يحسب الخادم SHA-256؛ إعادة رفع البايتات نفسها لنفس المصدر تعيد النتيجة نفسها، ورفع أصل مختلف لنفس المصدر يرفض.
- التحميل للأدمن فقط كمرفق `application/octet-stream` و`no-store` مع `nosniff` واسم تنزيل يولده الخادم. لا عرض inline أو تنفيذ HTML، ولا وصول عام أو مفاتيح أو خدمة تخزين مدفوعة.
- لا نسخة إنتاجية أو تفعيل للحصة/التخزين على قاعدة المشروع قبل موافقة تشغيل منفصلة. سياسة الاحتفاظ النهائية والنسخ الاحتياطي والمسح النظامي تراجع قبل النشر.

## API المقترح — إضافة محمية ومعطلة افتراضيًا

تحت `/api/admin/market`؛ ADMIN من الجلسة مع إعادة فحص الدور الحالي على الخادم، وCSRF لكل كتابة، و`Cache-Control: no-store`. الميزة خلف `rushd.market.enabled=false`؛ عند التعطيل لا تستعلم جداول غير موجودة. لا مسارات عامة أو تعديل لمسارات العقار أو المطابقة.

| العملية | العقد المختصر |
|---|---|
| `GET /sources` و`GET /sources/{id}` | قائمة محدودة وصفحات وبيانات المصدر دون بايتات الأصل |
| `POST /sources` | إنشاء مصدر بمعرف محاولة UUID ثابت وبياناته؛ الإعادة المطابقة لا تكرر الإنشاء |
| `PUT /sources/{id}/original` | أصل ثنائي محدود؛ التحقق من ADMIN وCSRF قبل القراءة |
| `GET /sources/{id}/original` | تنزيل خاص للأدمن فقط |
| `PUT /sources/{id}/state` | أرشفة/إعادة إتاحة بسبب ورقم مراجعة متوقع، دون تبديل الملف |
| `GET /references` و`GET /references/{id}` | أحدث إصدار مع أعلام نقص وصفية، دون حكم سعر أو eligible=true |
| `POST /references` | إدخال يدوي مرتبط بمصدر جاهز؛ معرف ثابت يمنع إعادة الإنشاء عند ضياع الرد |
| `PUT /references/{id}` | استبدال كامل معلن لحقائق المرجع مع expectedRevision وسبب؛ ينشئ إصدارًا ولا يمحو السابق |
| `PUT /references/{id}/state` | أرشفة/إعادة إتاحة صريحة مع سبب ومراجعة، لا حذف نهائي |
| `GET /references/{id}/versions` | تاريخ إصدارات مقسم على صفحات، للأدمن فقط |

رموز الرفض: 400 للمدخلات؛ 401/403 للمصادقة والصلاحية/CSRF؛ 404 للمفقود؛ 409 للتعارض أو تبديل أصل محفوظ أو تكرار هوية مصدر؛ 413 للحجم؛ 503 عند تعطيل الميزة. تفاصيل API النهائية وأمثلة JSON توثق مع التنفيذ المعتمد.

## الواجهة والاختبارات

- صفحة منفصلة `/admin/market-references` ورابط يظهر للأدمن عند تفعيل الإعداد التجريبي فقط؛ لا تغيير للثيم أو صفحات الزائر أو افتراض أن إخفاء الرابط حماية.
- قسم مصادر وقسم مراجع، مع نص واضح بأن الحفظ ليس تقييمًا، وبقاء قيم النموذج عند فشل حفظ/رفع أو تعارض. لا يرفع الملف بمجرد اختياره، ولا تمحى مسودة عقار أو صورها عند إدارة مرجع.
- لا تعرض الواجهة حالة «مؤهل»؛ تعرض أسبابًا مثل نقص النوع/معنى المساحة/الحي/العدد أو المصدر المؤرشف، مع بقاء القواعد الإحصائية والتحليل لـP21.
- اختبار حدود النصوص/الأعداد/التواريخ والكسور والأسّ الضخم والعربية والفارسية، النقص الصحيح والتعارض والتكرار، ونسخ التعديل والأرشفة، والملف غير المناسب/الكبير والرفع المتزامن/الحصة ورد ضائع.
- اختبار ADMIN/BUYER/ضيف وCSRF وno-store، عدم جلب المصدر من الشبكة أو تسريب الملف للعامة، وثبات R1/R3 والعقارات والمصادقة.
- `mvn clean test` في نسخة مؤقتة وPostgreSQL معزول مع validate والترقية من قاعدة فارغة وقاعدة سابقة، و`npm test/build/lint` ورحلة متصفح معزولة. لا SQL أو بيانات اختبار في قاعدة المشروع، ولا restart لخدمات المستخدم أو commit/merge/push.

## ما يبقى خارج هذا الاعتماد

اعتُمدت القرارات الثلاثة صراحة: الإدارة مشتركة للأدمن، والإصدارات والأرشفة دون حذف نهائي، والأصل XLSX بحد 10MiB وحصة 100MiB. التفعيل أو تطبيق SQL على قاعدة المشروع أو الاستضافة أو الاستيراد الآلي أو التحليل السعري غير مشمول. الأهلية الإحصائية وحدود التصنيف من P21 تحتاج عينة مؤهلة وقرارًا مستقلًا. نجاح اختبارات P20 لا يثبت صحة مصدر رسمي أو حق نشره ولا يقدّم ضمان فحص برمجيات خبيثة شاملًا.
