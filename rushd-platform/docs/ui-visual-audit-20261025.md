نطاق الطلب: فحص الواجهة بصريًا أولًا، ثم إصلاح مشاكل الأزرار وغيرها ضمن الهوية البيج والعنابي وخط Thmanyah. ليست P16 أو تغييرًا لمتطلبات التقييم. الفرع `feature/property-google-location`، والتعديلات السابقة الكبيرة محفوظة؛ لا تنسب كلها لهذه المراجعة. لا dependencies أو مفاتيح جديدة ولا commit/merge/push.

## ما ظهر قبل التعديل وما أُصلح

| المشكلة المرصودة | الإصلاح |
|---|---|
| تفاصيل البطاقة بعرض كامل، ثم حفظ ومقارنة بعروض متفاوتة، دون فاصل بين التفاصيل والحفظ؛ مؤشر التركيز يتداخل مع الجار | مكون `PropertyActions` مشترك: تفاصيل أساسية عنابية، ثم حفظ/مقارنة ثانويتان، بعرض متسق وفواصل12px وحد أدنى48px |
| ارتفاع العناوين المتفاوت يترك إجراءات بطاقات الصف على مستويات مختلفة | جسم البطاقة flex وإجراءاتها في نهايته؛ لا قص للعناوين |
| أزرار R3 موزعة قبل الحقائق وبعدها | الحقائق والأسباب أولًا ثم مجموعة الإجراءات نفسها، دون تغيير ترتيب المطابقة أو شروطها |
| نموذج الدخول أسفل لوحة تعريف طويلة على الجوال | النموذج أولًا في ترتيب DOM وعلى الجوال، مع بقاء لوحة الهوية يمينًا على الكمبيوتر؛ عنوان رئيسي واحد |
| حقول الدخول يمكن أن تظهر أثناء استعادة الجلسة ثم تعاد تهيئتها | رسالة انتظار قبل عرض الحقول حتى تنتهي استعادة الجلسة؛ لا تغيير لعملية الدخول أو صلاحياتها |
| سعر العقار والتواصل يأتيان بعد كل المواصفات على الجوال | تقديم بطاقة السعر والتواصل داخل التخطيط أحادي العمود؛ لم تضغط روابط الاتصال/واتساب في الاختبار |
| كسور السعر تنزل لسطر منفصل داخل بطاقة تابلت ضيقة | تخطيط أحادي العمود حتى900px وخط حسب عرض بطاقة السعر، مع منع فصل الرقم عن كسوره |
| أزرار حفظ الأدمن وإجراءات الصفوف غير متسقة على الشاشات الصغيرة | حفظ كامل العرض، وإجراءات صف الإدارة في شبكة واضحة، مع الحفاظ على الحقول والمدخلات |
| تعليمات المقارنة تسبق الجدول بنصوص طويلة وأزرار في صف مكسور | توضيح مختصر دائم، والتفاصيل داخل disclosure أصلي «كيف أقرأ المقارنة؟»، وزر تحديث رئيسي يليه الاختيار والمسح |
| التمرير الأفقي يفقد اسم المواصفة، وعمود العقار قد يكون أعرض من المساحة المتبقية على الهاتف | عمود مواصفة sticky باتجاهRTL، وأعمدة محسوبة لتعرض عقارًا كاملًا بجانبه؛ التمرير داخل الجدول فقط |
| الحد الأقصى للسعر كان يمكن أن يُقص على320px | تنسيق أصغر للأرقام الطويلة فقط، وتخفيف حشو الخلية وعمود المواصفة الصغير؛ لا Number أو تقريب أو تعديل للقيمة |
| GET حالة المفضلة404 يوصف كأن العقار نفسه غير متاح | صياغة مختلفة لفشل قراءة الحالة/القائمة عن404 الحفظ، دون افتراض نجاح أو تغيير membership |
| الشارة في بطاقة المفضلة تتمدد بعرض البطاقة | عرض بحسب المحتوى، وإجراء إزالة وحيد يمتد كامل المجموعة عندما تكون البيانات غير متاحة |

لم تُخف رسائل تعذر الصور والمفضلة ولم تُفعّل الخدمات على قاعدة المشروع لتجميل الشاشة.

## الملفات ودور كل منها

- جديدان: `frontend/src/components/PropertyActions.jsx` و`PropertyActions.css`؛ تركيب وتنسيق فقط فوق FavoriteButton/ComparisonButton القائمين، مع تمرير return state وpublicListing وremoveOnly دون تغيير سلوكها.
- `Properties.jsx` و`PropertyDetails.jsx` و`PropertyNeeds.jsx` و`Favorites.jsx`: استهلاك المجموعة بدل نسخ الإجراءات في كل صفحة. العقار المخفي في المفضلة يبقى بلا عنوان أو سعر أو رابط تفاصيل أو مقارنة، مع إزالة فقط.
- `ComparisonButton.jsx`: أيقونة المقارنة الموجودة لتوضيح الغرض، دون مكتبة أيقونات جديدة.
- `Login.jsx`: ترتيب DOM وعناوين دلالية وواجهة انتظار استعادة الجلسة. الحساب التجريبي وقواعده وأسراره المحلية لم تتغير.
- `PropertyComparison.jsx` و`PropertyComparison.css`: ترتيب الأزرار والتعليمات وdisclosure وعرض الأعمدة والخلية الرقمية والعمود الثابت؛ لا تغيير خوارزمية أو بيانات المقارنة أو حدود الاختيار.
- `index.css`: اتساق محاذاة الأزرار والتركيز، وعدم تحريك هدف الضغط عند hover، والتفاف رسائل التعذر دون ضغط زرها.
- `Pages.css` و`Management.css` و`PropertyCatalog.css` و`PropertyNeeds.css` و`Favorites.css`: مرونة البطاقات، ومحاذاة الإجراءات، وترتيب الدخول والسعر على الهاتف والتابلت، وحفظ الأدمن والشارات، وحجم مناسب للأسعار الطويلة.
- `services/favorites.js`: صياغة404 حسب العملية status/list/write فقط، دون endpoint جديد أو تغيير حفظ/إزالة أو ملكية أو retry semantics.
- `services/favorites.test.js` و`propertyComparison.test.js` و`uiLayout.test.js`: اختبار رسالة الخطأ، وتحديث فحص الربط للمكون المشترك، وحواجز مصدرية للتنسيق؛ لا تدعي هذه الاختبارات وحدها صحة العرض المرئي.
- `docs/design.md` وهذا التقرير: توثيق النتيجة والقيود.

### الفحص البصري والمتصفح

بدأ الفحص من النسخة المحلية القائمة على5173/8080، قبل أي تعديل: الرئيسية، التصفح والبطاقات، الدخول، حساب الأدمن التجريبي المحلي، نموذج الإضافة وقسم الموقع، تفاصيل عامة، المقارنة، وR1/R3. لم يُحفظ أو يعدل عقار من نموذج الأدمن، ولم تُرسل رسالة أو يُجر اتصال أو يرفع ملف. انتهت جلسة الأدمن المحلية بالخروج، ولم تُعد تشغيل خدمات المستخدم أو Docker.

بعد الإصلاح جُربت شاشات الكمبيوتر1024 والجوال390 و320، مع فحص DOM للأبعاد ومشاهدة screenshots فعلية:

- على390px: عرض الأزرار الثلاثة في البطاقة304px وارتفاع48px لكل منها، وفرق مواضعها60px (فاصل12px). لا تداخل بين حدود التركيز وأزرار الجوار، وعرض المستند390px.
- على1024px: بدايات مجموعات الإجراءات للبطاقات الثلاث الأولى على المستوى نفسه (y≈490px في اللقطة)، وعرض المستند1024px.
- دخول390px: حقل البريد يبدأ عندy≈362، وزر الدخول ينتهي عندy≈586، داخل الشاشة دون النزول أسفل لوحة التعريف.
- تفاصيل390px: بطاقة السعر تبدأ قبل قسم المواصفات (في الفحص y≈1018 مقابل1651)، والاتصال والواتساب واضحان مع مؤشر تركيز فاتح فوق العنابي. الأرقام وروابطهما لم تتغير.
- تفاصيل821px: اكتُشف فصل كسور السعر في التخطيط القديم؛ بعد الإصلاح ظهرت `850٬000٫00` في سطر واحد، وبقي عرض المستند821px والسعر قبل المواصفات.
- نموذج الأدمن الصناعي320px: زر الحفظ242px يساوي عرض مجموعة الإجراءات، وارتفاع50px، دون تمدد المستند؛ جُرب تغيير النوع لشقة وفتح بيانات الموقع دون submit.
- مقارنة320px: الحد الأقصى `99999999999999999.99` يعرض `99٬999٬999٬999٬999٬999٫99` كاملًا؛ عرضه الفعلي≈181.3px ضمن مساحة محتوى185px. لا قص أو تحويل عبر Number، وعرض المستند320px.
- جُرب Tab ومؤشر التركيز، وتمرير الجدول الأفقي مع بقاء اسم المواصفة ثابتًا. ليس هذا تدقيق قارئ شاشة أو وصول شاملًا.

### المفضلة والحالات الخاصة: تحقق معزول

أُنشئت بيئة مؤقتة مستقلة على127.0.0.1:5176/18086 بقاعدة PostgreSQL tmpfs وحسابات ADMIN/BUYER وعقارات صناعية. استُخدم runner الاختبار المحلي المملوك السابق مع إعداد المفضلة في **المعزول فقط**؛ لم تفعّل علىdb_rushd.

- تسجيل دخول BUYER وحفظ أرض من البطاقة، وإضافتها للمقارنة، ثم مشاهدة نفس الحالة في المفضلة.
- حفظ شقة ثانية، ثم إخفاؤها عبر API الأدمن في القاعدة المؤقتة. قائمة المفضلة أظهرت خانة بلا بيانات وزر إزالة فقط؛ أزيلت بنجاح وأصبح العدد1.
- المقارنة حدّثت السعر وأخفت بيانات الشقة دون تسريب عنوانها الخاص. قيمة السعر القصوى عُدلت على العقار الصناعي فقط لاختبار العرض عند الحد.
- R1/R3 في النسخة المحلية أعادت أرضًا واحدة ضمن الميزانية، مع استمرار الحقائق والأسباب وmatching-v1؛ الأزرار انتقلت فقط إلى نهاية البطاقة.

الصور في هذه الجولة فُحصت بحالة التعذر/البديل فقط. لم يعاد رفع صور أو اختبار معرض ممتلئ، ولم تُغيّر عمليات الرفع أو التخزين أو أمانها. رسائل المفضلة في النسخة الجارية لا تعني أن الميزة فعّلت؛ التحقق الناجح كان في المعزول.
