- عرضت أثر توسيع مرشح المدينة قبل تعديله. اعتمد المستخدم: **«نعم، اجمع صيغ مكة المعتمدة (المقترح)»**؛ تشمل «مكة»، «مكة المكرمة»، و«Makkah»، مع تجاهل حالة الأحرف والمسافات الزائدة، دون كتابة بيانات أو تغيير المدن الأخرى. لا تخمين «Mecca/مكه».

## التنفيذ

1. الواجهة تعرض مكة بنطاقها المعتمد، والحي والنوع ونطاق السعر والبيع/الإيجار وفترته. لا مرشحات مواصفات أو ترتيب سعري جديدة. التصفح العام منفصل عن المطابقة الشخصية P06.
2. التطبيق بزر صريح. تعديل المسودة يلغي الطلب السابق ويخفي نتائجه؛ التطبيق يبدأ من الصفحة صفر، والتنقل بين الصفحات يحفظ المرشحات كاملة.
3. URL مصدر حالة البحث المطبقة؛ التحديث وBack/Forward يستعيدانها. رابط العودة من التفاصيل يحفظ نفس البحث والصفحة عبر مسار داخلي متحقق منه فقط، دون redirect خارجي أو localStorage.
4. الرابط غير الصالح/المكرر/ذو معاملات غير مدعومة لا يصبح بحثًا أوسع بصمت؛ الأخطاء والمدخلات تبقى حتى التصحيح والتطبيق أو المسح. الصفحة التي خرجت من النطاق تعرض استعادة صفحة متاحة بنفس المرشحات.
5. استخرجت بوابة الإلغاء العامة من propertyMatches إلى requestGate، مع إعادة تصدير الاسم القديم دون تغيير عقد P06 أو خوارزميتها. AbortController ورقم الجيل يمنعان النجاح والفشل المتأخرين، حتى لو تجاهل النقل الإلغاء.
6. القائمة العامة تضيف `id,desc` عند تعادل حقل الترتيب الأساسي؛ `sort=id,asc/desc` يحتفظ باتجاهه. لا تغيير للحالات غير المتعادلة أو ترتيب قائمة الأدمن. هذا ليس snapshot للمخزون المتغير بين طلبَي صفحات.

## السعر والحدود

- «كل العروض» و«إيجار شهري وسنوي» متاحان دون نطاق سعر، وكل بطاقة تعرض وحدتها الفعلية. لتطبيق مبلغ يجب اختيار SALE أو RENT مع MONTHLY/YEARLY صراحة؛ لا تحويل أو فترة افتراضية.
- تبديل الوحدة يحفظ المبالغ، لكنه يحتاج مراجعة صريحة قبل استعمالها بوحدة أخرى، أو مسح نطاق السعر. لا حذف أو إعادة تفسير صامتة.
- minPrice/maxPrice اختياريان من `0` إلى `99999999999999999.99`، بحد 17 خانة صحيحة ومنزلتين عشريتين دون تقريب. الصفر حد بحث صالح، وليس سعر إنشاء صالحًا. العربية/الفارسية والفاصل العربي تطبع إلى ASCII؛ السعر لا يمر عبر Number، والمقارنة عشرية دقيقة.
- الحي حتى 100 حرف دون محارف تحكم. المقارنة الحالية حرفية بعد trim للمدخل وتجاهل حالة الأحرف في API؛ لا إزالة «حي» أو توحيد المسافات الداخلية. تختلف عمدًا عن مقارنة الحي في المطابقة الشخصية؛ لم نوسعها.
- واجهة التصفح ثابتة على 12 نتيجة و`createdAt,desc`؛ page من 0 إلى 2147483647. Number يستخدم للصفحات الآمنة فقط. عقد API لحجم الصفحة 1–100 والترتيبات المدعومة لم يتغير.

## أثر API وDB والحماية

نفس `GET /api/properties` ونفس المعاملات والاستجابة. **تغيير city المعتمد** يجمع صيغ مكة الثلاث قبل العد والصفحات، مع تطبيع المسافات في SQL للمقارنة فقط. المدن الأخرى تبقى على المطابقة السابقة، وغياب city في API المباشر ما زال يعني عدم ترشيح المدينة؛ الواجهة تضيف مكة افتراضيًا.

مثال للقراءة؛ الواجهة ترمز العربية بواسطة URLSearchParams:

```http
GET /api/properties?city=مكة المكرمة&district=حي الياسمين&type=APARTMENT&listingType=RENT&rentalPeriod=MONTHLY&minPrice=3000.50&maxPrice=4500.75&page=0&size=12&sort=createdAt,desc
```

جزء مختصر من الاستجابة؛ بقية حقول العقار والصفحات باقية:

```json
{
  "content": [{ "id": 20, "price": "4500.75", "listingType": "RENT", "rentalPeriod": "MONTHLY" }],
  "page": 0,
  "size": 12,
  "totalElements": 2,
  "totalPages": 1
}
```

الطلبات الرقمية القديمة الصحيحة وعقود الكتابة لم تتغير. **حاجز خلط وحدات السعر وحدود إدخال الواجهة ليس تغييرًا للتحقق في API**: العملاء المباشرون ما زالوا يستطيعون طلب أسعار مسجلة عبر فترات/أنواع مختلطة وفق العقد السابق، وعليهم تفسيرها بوحداتها. لا يدعي P08 تشديدًا عامًا لمعاملات البحث.

لا schema أو migration أو بيانات فعلية أو مفاتيح أو dependencies جديدة. ACTIVE-only للقائمة، وADMIN والتفاصيل الخاصة وHttpOnly وCSRF كما هي. لا تمرير معاملات URL عشوائية إلى API، ولا HTML حر أو رابط خارجي في العودة. لا صور أو خرائط أو AI أو تغيير للثيم والخط.

### المتصفح

خادم Spring/Vite فعلي وقاعدة PostgreSQL tmpfs جديدة على loopback، مع 34 عقارًا عبر API العادي؛ لا fixtures على db_rushd.

- نطاق مكة أعاد 30 عقارًا، مستبعدًا المدينة الأخرى وثلاث حالات غير ACTIVE. السعر `9007199254740993.01` بالعربية/الفارسية أعاد العقار نفسه، لا جاره ذي `.02`.
- الشقق للبيع في «حي الياسمين»: 18 نتيجة، 12 ثم 6 دون تكرار؛ reload وBack/Forward والعودة من التفاصيل استعادوا الحالة، وتغيير النوع صفّر الصفحة.
- الشهرية أعادت عقاري الشهر فقط، والسنوية عقاري السنة بوحداتها. التبديل بالمبالغ السابقة رفض قبل المراجعة؛ الفترة غير المحددة مع مبلغ رفضت، ومسح السعر أتاح الفترتين دون تحويل.
- `1e99999999` رفض وبقي في المدخل. عدم التطابق أعاد صفرًا دون تخفيف. صفحة99 عرضت استعادة صفحة بنفس المرشحات؛ الرابط المكرر رفض ثم أصلح بتطبيق صريح.
- أوقف خادم الاختبار المملوك مؤقتًا فقط: المهلة أظهرت خطأ دون نتائج قديمة، وحفظت المبلغين، ونجحت إعادة المحاولة. تعديل الحي أثناء طلب معلق ألغاه؛ بعد الاستئناف لم يظهر رد أو فشل متأخر. لم يوقف خادم المستخدم.
- عروض320/390/681/1280 دون تجاوز أفقي، وكل سعر حساس في سطر واحد وداخل بطاقته. روجعت لقطة سطح المكتب العادية والجوال. اللقطات المعتمدة المؤقتة: `/tmp/rushd-p08-review/catalog-final-desktop.png` و`catalog-mobile.png`.

## التجربة اليدوية وحدود التحقق

بعد إعداد بيئة معزولة، أو تفعيل ترقية P04 باعتماد منفصل ونسخة احتياطية: افتح `/properties`، واختر البيع والحي والنوع والسعر ثم طبق. انتقل للصفحة التالية، حدث المتصفح، وافتح التفاصيل ثم عد. بدّل إلى إيجار وفترة محددة وراجع المبالغ أو امسحها. جرّب صيغة أسية أو أعلى أقل من الأدنى ثم صحح؛ وحيًا غير موجود وصفحة خارج النطاق.

ترقية P04 **لم تطبق على قاعدة المشروع الفعلية**؛ لا تشغل الكود على المخطط القديم أو تستعمل ddl-auto=update كحل سريع. أزيلت موارد الاختبار المملوكة وأغلق التبويب وأعيد viewport، دون إعادة تشغيل Docker أو خدمات المستخدم. لا commit/merge/push.

لا اختبار أحمال أو نشر فعلي أو كل المتصفحات/قارئات الشاشة. تطبيع مدينة مكة في SQL يحتاج قياس أداء وخطة فهرسة عند كبر البيانات؛ لم نغير المخطط. ثبات التعادل لا يمنع تغير المخزون بين طلبَي صفحات؛ recovery واضح لكن لا session snapshot. نجاح الاختبارات ليس ضمان أمان شاملًا أو جاهزية إنتاج.
