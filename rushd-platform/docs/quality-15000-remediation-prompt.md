## 2. الحزمة الأولى — المصادقة والتسجيل

### F01 — أولوية عاجلة

Spring Boot3.3.5 يحل Spring Security6.3.4، والمستخدم هو BCryptPasswordEncoder. التسجيل بكلمة يزيد طولها عن72 بايت ثم الدخول بكلمة تختلف بعدها فقط نجح، في ASCII والعربية. اثنتا عشرة حالة من الفشل تخص ذلك: `backend.bcrypt-distinct-password.0` إلى`.9`، و`http.auth-password-distinct.0/.1`.

راجع [CVE-2025-22228 الرسمي](https://spring.io/security/cve-2025-22228/) وحالة دعم/تنبيهات الإصدارات الحالية من المصادر الرسمية عند التنفيذ. لا تفترض أن اختيار أول patch قديم وحده يغلق كل مخاطر2026.

- راجع توافق BOM ثم اقترح ترقية مدعومة ومختبرة، لا `audit fix --force` ولا ترقيات عشوائية.
- حدد سياسة طول ببايتات UTF-8 للتسجيل والدخول؛ ضع خطة توافق/استرداد للحسابات القديمة ذات كلمات المرور الطويلة، واطلب اعتماد أثرها قبل تغييرها.
- لا تقص كلمة المرور أو تغير معناها، ولا تضف pre-hashing أو تبدل الخوارزمية صامتًا.
- اختبر72/73 بايت، ASCII والعربية، suffix مختلفة، تغيير داخل البادئة، وكلمات عادية صحيحة/خاطئة. الرفض الآمن لطول غير مدعوم مقبول وفق السياسة المعتمدة؛ لا تعتبر exception غير معالجة نجاحًا أمنيًا.

### F02 — حدود التسجيل

اسم أطول من255 يعيد500 من PostgreSQL بدل400 قبل DB؛ ثماني حالات `http.auth-registration-length.5/.6/.7/.8/.15/.16/.17/.18`.

طبّق حدودًا متوافقة في DTO، وراجع البريد أيضًا. احتفظ بتمييز null/blank/الطول، واختبر العربية والحدود. لا تحوّل كل خطأ قاعدة إلى400 كبديل للتحقق.

### F03 — سباق البريد المكرر

طلبان متزامنان يعيدان201 و500 بدل201 و409. القيد الفريد صحيح؛ الفحص المسبق لا يمنع السباق. حالتا `http.auth-duplicate-race.0/.1` تثبتانه.

احتفظ بالقيد، وترجم تعارض البريد المحدد إلى409 دون إخفاء بقية أخطاء القاعدة. أضف اختبار تزامن متحكمًا فيه وPG حقيقيًا، إضافة إلى HTTP المتزامن.

مراجعة تقوية منفصلة: register العام خارج محدد معدل login/refresh؛ ضع سياسة منع إساءة التسجيل مناسبة دون إغراق خدمات المستخدم أو الثقة في forwarded headers عشوائية. لا تغير الصلاحيات أو تستحدث MFA/خدمة خارجية دون اعتماد نطاقها.

## 3. الحزمة الثانية — API والعقد والاختبارات

### F04 — HTTP500 بدل405/415

GET إلى login/register أو إرسالtext/plain يعيد500 عبر المعالج العام؛ أربع حالات `http.auth-protocol.0–3`.

أعد أكواد MVC الصحيحة وجسم الخطأ الموحد، وAllow عند اللزوم، مع سجل داخلي آمن للأخطاء الحقيقية. لا تكشف stack trace أو Cookie/Set-Cookie أو كلمات المرور. اختبر كذلك malformed JSON وCSRF والصلاحيات حتى لا يختلط خطأ محتوى بطريق تجاوز صلاحية.

### F05 — قبول ترتيب enum

التدقيق أثبت `type:0`→LAND، والمصفوفة أثبتت `role:0`→BUYER بـ201 بدل400 (`http.auth-role.2`). لم يثبت تصعيد إلىADMIN، فلا تصفه بذلك.

راجع عقد Create/Update/Register، وطبق قراءة محلية صارمة لأسماء enum عند اعتماد أثر التوافق، مع رفض الأرقام/الأسماء غير المعروفة. لا تغير Jackson عالميًا لإصلاح DTO محلي، ولا تستبدل الأرقام المالية بـNumber. حافظ على النصوص العشرية الخمسة وBigDecimal وnullable وطلبات الأرقام القديمة الصحيحة حيث يدعمها العقد.

### F06 — الأمر الافتراضي للاختبارات

`mvn clean test` ما زال يفشل13 حالة: H2 يرفض معامل`g` في regexp_replace لمرشح مكة.621 على PostgreSQL المعزول نجحت.

أصلح استراتيجية/إعداد الاختبار الافتراضي بصورة واضحة، مع استمرار تحقق صيغ مكة والفرز وحدود السعر علىPG. لا تحذف الحالات أو تعطلها أو تغير قواعد الموقع لإرضاء محرك اختبار مختلف، ولا تسجل نجاح أمر لم ينجح.
