# P05 — فورم الأدمن وعرض مواصفات العقار

التاريخ: 19 أكتوبر 2026. النتيجة: **اكتمل إدخال وعرض مواصفات P04، واختُبرت الرحلة مع PostgreSQL معزول. لم تُرقَّ قاعدة المشروع الفعلية ولم تُعَد تشغيل خدمات المستخدم.** المرجع: [المعاني P03](p03-property-specifications-draft.md)، و[العقد P04](p04-property-specifications-proposal.md)، و[API العقارات](api-properties.md).

الفرع `feature/property-google-location` وشجرة Git يحتويان عملًا سابقًا محفوظًا؛ لا تُنسب كل التعديلات إلى هذه الدفعة.

## ما تغير ولماذا

كان الباكند يخزن 37 معلومة منظمة، لكن الفورم والتفاصيل لا يعرضانها. إرسال كل الحقول الفارغة كـnull في كل تعديل كان سيمحو بيانات لا يقصد الأدمن تعديلها، وتحويل المساحات إلى Number كان سيعيد خطر التقريب الذي عولج في T01/T02.

- قاموس واجهة واحد للحقول وأنواعها وتسمياتها العربية ومجموعاتها وحدودها وخياراتها، مع مصفوفة انطباق مطابقة لـP04. يعاد استخدامه في الإدخال والعرض والتحقق، دون خلط المساحات والعدادات والإحداثيات.
- تظهر حقول الأنواع السبعة عند انطباقها فقط. نطاق التجاري اختياري، لكنه يحدد حقول الوحدة مقابل المبنى؛ لا يُخمّن من التصنيف.
- جميع المواصفات الجديدة اختيارية. نعم/لا/غير محدد، وقوائم الحالة والتشطيب والتأثيث مستقلة؛ الصفر وfalse محفوظان، ولا استنتاج لـ«جديد» أو «ستوديو» أو سنة بناء.
- تبقى المساحات نصوصًا طوال الإدخال والتحقق والإرسال والعرض. يعاد استخدام المحلل المشترك للأرقام العربية والفارسية والفاصل العشري العربي، والمقارنة الدقيقة دون Number. العدادات تتحول إلى JSON integer فقط بعد فحص الصيغة وحدود BigInt الآمنة الصغيرة؛ لا قص لكسور أو أسس.
- يختار الأدمن مصدر الرئيسية صراحة من مساحة مدخلة، أو «معلنة غير مصنفة». عند الربط تعرض الرئيسية من المصدر للقراءة فقط دون إعادة إدخال. فك الربط الصريح يحفظ القيمة الحالية غير مصنفة، ولا يختار مصدرًا آخر.
- تقارن المواصفات بالحالة الأصلية؛ يرسل التعديل الحقول المتغيرة فقط، وnull صريحًا للممسوح. عند عدم تغيرها يغيب القسم تمامًا. تغيير أحد جزئي العمر يرسل الزوج، ومسحهما يجب أن يكون معًا.
- مسودات الأنواع ونطاقَي التجاري تبقى في ذاكرة النموذج عند التنقل، دون localStorage أو حفظ دائم. تغيير نوع عقار محفوظ أو نطاقه يعرض الحقول التي لن تنطبق ويطلب تأكيد الإزالة أو الإلغاء. فقد مصدر الرئيسية يوضح أثر فك الربط؛ التأكيد لا يحفظ إلى الخادم حتى الضغط على الحفظ.
- فشل الشبكة أو التحقق لا يعيد تهيئة المدخلات. أخطاء الخادم الحقلية مرتبطة بالحقول. ملخص الأخطاء والتأكيد قابلان للتركيز، ويعود التركيز إلى اختيار النوع/النطاق بعد القرار.
- تعرض التفاصيل الحقول المنطبقة والوحدات ومصدر المساحة، والعمر كتقدير مؤرخ لا يزداد آليًا. الناقص «غير محدد»، والأرقام داخل bdi باتجاه LTR ضمن RTL. لا استنتاج تجهيزات مبنى لوحدة أو خدمات قريبة أو خصوصية مسبح.

## أثر API والقاعدة والحماية

لا تعديل للباكند أو عقد API أو المخطط في P05؛ تستخدم الواجهة P04. مثال جزء من PUT عند مسح المصعد وتغيير العمر فقط:

```json
{
  "specifications": {
    "hasElevator": null,
    "estimatedAgeYears": 9,
    "ageAsOfYear": 2026
  }
}
```

هذا جزء من الطلب، وليس PUT كاملًا؛ الحقول القديمة المطلوبة ما زالت ترسل وفق عقدها السابق. بقية المواصفات غائبة فتحفظها الخدمة. المساحات الجديدة ترسل مثل `"unitNetArea": "150.25"`، لا عددًا عشريًا من JavaScript. اختلاف الأصفار النهائية ليس تغييرًا في القيمة العددية.

تحقق الواجهة لتحسين الإدخال، لا بديلًا عن الخادم. بقيت ADMIN-only وHttpOnly cookies وCSRF و401/403 وإخفاء المسودات وقواعد النشر كما هي. استخدم عميل API الحالي، دون دخول أو صلاحيات جديدة. لا مفاتيح أو dependencies أو مزود خارجي.

**تنبيه تشغيل:** كود P04/P05 يتوقع أعمدة spec_. [الترقية السابقة](../backend/db/20261018-property-specifications.sql) اختُبرت معزولة ولم تُطبّق على db_rushd. يلزم نسخ احتياطي ومراجعة واعتماد تفعيل منفصل قبل تشغيل النسخة على المخطط الفعلي القديم. لا ddl-auto update أو إعادة baseline أو Docker لمعالجة الفرق.

### تجربة المتصفح الفعلية

React/Vite وخادم Spring Boot فعليان على loopback، مع PostgreSQL جديد في حاوية tmpfs مملوكة للاختبار. طُبق baseline وترقية P04 هناك فقط. أنشئ حساب fixture عادي ورُفع دوره داخل القاعدة المعزولة فقط لاستخدام الدخول الحالي؛ لا تجاوز للمصادقة في التطبيق. عطلت إعدادات زر الديمو وبياناته في عملية الواجهة المعزولة، ولم تستخدم بيانات الحساب الحقيقي.

جُربت الإضافة والتعديل وإعادة الفتح والتفاصيل لكل الأنواع السبعة، ثم:

- السعر `9007199254740993.01` والمساحة `9999999999.99` بإدخال عربي/فارسي عادا دون فقدان دقة.
- أرض بمواقف 0 وكهرباء false ومياه true، وتعديل حقل واحد مع حفظ البقية.
- شقة بصافي/إجمالي، وغرف 0 ودور −10 وعمر مؤرخ؛ تبديل مسودة النوع والعودة حفظ القيم الخام. عدد غرف `٣٫٥` رفض دون إنشاء سجل أو مسح المدخلات.
- إلغاء تغيير نوع شقة محفوظة أبقى القيم؛ تأكيد التحول إلى فيلا مسح الصافي والإجمالي والدور والمصدر غير المنطبق صراحة، وأبقى غرف النوم 0 والعمر المتوافق. ثم مُسح زوج العمر وأعيدت قراءته null.
- التجاري كوحدة حفظ الدور 0، ثم إلغاء وتأكيد التحول إلى مبنى كامل، وإدخال الأرض والأدوار والوحدات ومصدر جديد؛ بقي التصنيف والحمامات، ومسحت حقول الوحدة.
- فشل اتصال مضبوط بإيقاف تنفيذ خادم الاختبار مؤقتًا بـSIGSTOP، لا خادم المستخدم: انتهت مهلة PUT، وظهرت رسالة اتصال مع بقاء المسودة وزر الحفظ. بعد SIGCONT نجح الحفظ. مهلة العميل لا تثبت أن الخادم لم ينفذ الطلب؛ التجربة كانت على PUT للمعرف نفسه، لا إعادة إنشاء عمياء.
- عقار دون مواصفات جديدة بإيجار شهري وحالة DRAFT وإحداثيات −90 و180: بقيت المواصفات مجهولة، وحالة المسودة والفترة والإحداثيات محفوظة.
- فحص SQL على الحاوية المملوكة أكد ثمانية سجلات اختبار والقيم الدقيقة ومسح غير المنطبق والزوج وحفظ الغائب، وأن جميع أعمدة spec_ للعقار الذي لم يرسل المواصفات بقيت null.
- على 320 و390 و681 و1280 بكسل: لا تجاوز أفقي للصفحة أو رموز الأرقام داخل خلايا المواصفات. روجعت لقطات الفورم والتفاصيل، والخط المحسوب Thmanyah Sans؛ لا تغيير للبيج/العنابي.

أوقفت عمليات الاختبار وأزيلت الحاوية المملوكة، وأغلق تبويب المعاينة وأعيد ضبط viewport. لا SQL أو fixtures أو إعادة تشغيل على قاعدة المشروع أو خدمات المستخدم. لقطات المراجعة مؤقتة في `/tmp/rushd-p05-review/`، وليست ميزة صور عقارات.

## تجربة يدوية وحدود الإغلاق

على بيئة معزولة أو بعد ترقية معتمدة ونسخة احتياطية:

1. سجل الدخول كأدمن وافتح الإدارة. اختر شقة وأدخل الأساسيات والصافي والإجمالي بالأرقام العربية أو الفارسية، ثم اختر مصدر الرئيسية صراحة.
2. اترك المجهول فارغًا؛ جرّب غرفًا 0 ومصعدًا «لا»، واحفظ. أعد فتح التعديل والتفاصيل للتحقق من القيم.
3. غير تجهيزًا واحدًا؛ تأكد أن البقية بقيت. امسح العمر وسنته معًا، أو جرّب أحدهما لترى الرفض دون فقد المدخلات.
4. غيّر النوع أو نطاق التجاري: ألغِ أولًا ثم أكد وراجع الحقول قبل الحفظ. لا مصدر رئيسية بديلًا تلقائيًا.
5. جرّب كسرًا في عداد أو مساحة بثلاث منازل؛ يجب رفض الحفظ دون تقريب. راجع العرض على الجوال.

لم تختبر كل المتصفحات أو قارئات الشاشة أو أجهزة الجوال الفعلية، ولا النشر أو الأحمال أو نسخ/استعادة بيانات المشروع. مصفوفة الواجهة مستقلة وليست مولدة آليًا من Java؛ تغيير العقد لاحقًا يحتاج تحديث الطرفين واختباراتهما. المسودات ليست استرجاعًا بعد تحديث الصفحة. لا ضمان عام ضد تعارض تعديل الحقول القديمة من عميل قديم، ولا idempotency جديدة لإنشاء العقارات.
