# P03 — مواصفات الأنواع ومعاني المساحة المعتمدة

التاريخ: 18 أكتوبر 2026. الحالة: **مكتمل كحزمة قرار وتوثيق؛ اعتمد المستخدم الجدول الفني والتعريفات والتوافق، لا تنفيذ بعد**. أبقي اسم الملف `draft` لاستمرار الروابط السابقة؛ لم يعد وصفًا لحالة الاعتماد.

اعتمد المستخدم: حزمة موسعة، ومساحات منفصلة واضحة، وجميع الحقول الجديدة اختيارية؛ ثم اختار **عمرًا تقريبيًا بالسنوات مع سنة التقدير**، والقوائم الثلاث المستقلة، والتجهيزات العشرة كاملة. واعتمد اختيار مساحة رئيسية صراحة مع بديل غير مصنف، والحفاظ على المواصفات عند غيابها من الطلب وتأكيد إزالة غير المنطبق عند تغيير النوع، والتجاري كوحدة أو مبنى كامل مع تصنيف فرعي. وفي الجولة الأخيرة اعتمد الجدول الفني وتعريفات المساحات وحدوده، ورفض تعديل المساحة القديمة المتعارض فقط بـ400 دون فك ربط تلقائي، ودمج الحقول الجديدة المقدمة فقط مع مسح صريح لكل حقل. هذا اعتماد للمعاني والسياسات، لا تنفيذ لـP04/P05 ولا اعتمادًا مسبقًا لأسماء JSON أو تمثيل JPA أو migration؛ تعرض تلك التفاصيل وأثر API/schema في P04 قبل تغيير التطبيق.

## 1. نتيجة الفحص: الموجود فعلًا

راجعت Property وCreate/Update وResponse وMapper ونموذج الأدمن والتفاصيل وخدمات النموذج واحتياجات المستخدم وقواعد المطابقة والتوثيق. الأنواع السبعة موجودة: LAND/APARTMENT/VILLA/BUILDING/COMMERCIAL/FARM/OTHER. لا حقول منظمة للغرف أو الحمامات أو الأدوار أو الوحدات أو المصعد أو الخدمات حاليًا.

| المجموعة الحالية | القاعدة الموجودة | أثرها على التصميم |
|---|---|---|
| النوع والعرض والفترة | سبعة أنواع؛ SALE/RENT وفترة MONTHLY/YEARLY للإيجار | لا نحتاج إضافة نوع رئيسي لمجرد إظهار حقوله |
| المدينة والحي | مطلوبان؛ الموقع التفصيلي اختياري | لا تغيير ضمن P03 |
| `area` | مطلوب في Create/Update، numeric(12,2)، من0.01 إلى9999999999.99 | مساحة معلنة واحدة، دون بيان أرض/صافي/بناء |
| `price` | مطلوب، numeric(19,2)، من0.01 إلى99999999999999999.99 | سعر بيع أو قيمة فترة الإيجار، لا سعر متر |
| `streetWidth` | اختياري، numeric(10,2)، من0.01 إلى99999999.99 | موجود لكل الأنواع حاليًا؛ لا نجعله شرط أرض تلقائيًا |
| `facade` | enum للجهات مع UNKNOWN، وليس طول واجهة بالمتر | لا نخلط الاتجاه بطول الحد أو عدد الشوارع |
| `purpose` | استخدام مسجل مطلوب؛ `searchGoal` نية المستخدم | لا يثبت الترخيص أو الاستخدام المسموح أو جدوى الاستثمار |
| الأرقام الدقيقة | حقول العقار العشرية الخمسة تعود نصوصًا دقيقة | تبقى المساحات الجديدة دقيقة، لا Number أو تقريب صامت |
| PUT | تعديل كامل للحقول الحالية، وغياب اختياري قد يمسحه | لا نطبق هذه الدلالة آليًا على حقول جديدة فيمسحها عميل قديم |

نموذج الأدمن والتفاصيل يعرضان مساحة عامة واحدة. R3-v1 يقارن المساحة المعلنة داخل النوع نفسه فقط، وتوضح واجهة الاحتياجات أنها ليست بالضرورة صافيًا أو مساحة أرض. لا دليل يسمح بإعادة تفسير السجلات القديمة من النوع وحده.

### 3.1 العمر — النموذج المختار: تقدير بالسنوات مع سنة التقدير

اختيار المستخدم الصريح: «عمر تقريبي بالسنوات مع تسجيل سنة التقدير». **لم يختر سنة اكتمال البناء أو استخراج عمر منها**. النموذج المعتمد قيمتان: عمر تقديري وسنة التقدير؛ `estimatedAgeYears` و`ageAsOfYear` اسمان توضيحيان، والأسماء النهائية من عقد P04، وليستا حقولًا منفذة الآن.

الدلالات المعتمدة ضمن الجدول النهائي:

- العرض مثل «العمر التقديري:8سنوات — تقدير عام2026». يبقى تقديرًا مؤرخًا حتى لو عرض لاحقًا، دون زيادة تلقائية أو إعادة كتابة المخزون عند القراءة.
- لا نستخرج سنة بناء بطرح العمر من السنة، ولا نستعمل updatedAt بدل سنة التقدير. لا نجعل تجديد التشطيب صفرًا لعمر المبنى الأصلي.
- المجموعة اختيارية: كلاهما غائب، أو كلاهما مقدم. تقديم العمر وحده لا يفترض السنة الحالية؛ عند تعديل الزوج أو مسحه يقدم الحقلان معًا، ولا يقبل تغيير أحدهما منفردًا. هذه قاعدة اتساق، لا اشتراط لتعبئة العمر على كل عقار.
- الصفر تقدير معلوم لأقل من سنة، وليس unknown ولا اختيارًا تلقائيًا لحالة «جديد».
- لا نفترض عمرًا للأرض الخالية أو مبنى تحت الإنشاء. لا نحوّل مدة بدء الإنشاء أو عمر الترميم إلى عمر المبنى دون معلومة صريحة بالمعنى المتفق عليه.
- سنة التقدير ميلادية ولا تقبل المستقبل. الحد التقني المعتمد للعمر0..1000 ولسنة التقدير1900..السنة الحالية، وأعداد صحيحة بلا كسور؛ ليست حدودًا تاريخية أو سوقية عامة.

خيار سنة اكتمال البناء الذي عرض سابقًا غير مختار، ولا نضيفه بالتوازي كمصدر حقيقة ثانٍ ضمن هذه النسخة.

### 3.2 الحالة والتشطيب والتأثيث — القوائم والخيارات معتمدة

| المفهوم | الخيارات التي اعتمدها المستخدم | ما لا نستنتجه |
|---|---|---|
| حالة العقار | تحت الإنشاء / جديد / مستخدم | ليس تغييرًا لحالة النشر DRAFT/ACTIVE/INACTIVE/SOLD؛ ولا يعتمد على العمر آليًا |
| اكتمال التشطيب | غير مشطب / جزئي / كامل | لا تصنيف جودة فاخر/اقتصادي ولا حكم على السعر |
| التأثيث | غير مفروش / جزئي / كامل | لا يعني وجود تكييف أو مطبخ راكب تلقائيًا |

كل قائمة اختيارية تقبل «غير معلوم» كقيمة غائبة، ولا خيار افتراضي يدعي معرفة. «عظم» يشرح في الوصف ضمن مستوى التشطيب الملائم إلى أن يعتمد تعريف مستقل. الشقة المستخدمة قد تكون مفروشة بالكامل أو غير مفروشة، والمطبخ الراكب لا يثبت تأثيثها الكامل. لم يختر المستخدم بديل الوصف الحر فقط. لا نستبدل حالة «تحت الإنشاء/جديد/مستخدم» بحالة صيانة مختلفة لم يعتمدها، ولا نضيف تصنيفًا سعريًا أو «فاخرًا» تلقائيًا. حدود الانطباق معتمدة بالجدول؛ أسماء enums الفنية النهائية من عقد P04.

### 3.3 التجهيزات — المجموعة الموسعة معتمدة

اختار المستخدم «المجموعة الموسعة المقترحة كاملة»: مصعد يخدم العقار، عدد مواقف مخصصة، تكييف مركب، مطبخ راكب، غرفة عاملة، غرفة سائق، مسبح، حوش، شرفة، سطح خاص. هذه القائمة نفسها معتمدة، لا مجرد مستوى تفصيل عام؛ خيار الأربعة الأصغر غير مختار. تبقى جميعها اختيارية، واعتمد توزيعها على الأنواع في الجدول أدناه.

- الوجود true/false/null، والمواقف عدد أو null. لا نخزن عدد مواقف وفوقه Boolean منفصلًا يناقضه.
- غرفة العاملة/السائق تعني وجود الغرفة ضمن المعروض، لا معلومات عن أشخاص أو خدمات بشرية.
- «سطح خاص» صريح في الخصوصية. المسبح والحوش والشرفة لا توصف تلقائيًا بأنها خاصة؛ وجود تجهيز متاح ضمن العرض لا يثبت انفراد المستخدم به. لا ننسب مرفقًا مشتركًا إلى كل وحدة بوصفه خاصًا، ولا ترث الوحدة تجهيزات العمارة دون معلومة صريحة.
- المصعد قد يكون مشتركًا لكن يجب أن يخدم موضع المعروض. «تكييف مركب» لا يثبت تغطية كل الغرف أو حالته الفنية، والمطبخ لا يثبت وجود أجهزة كهربائية أو تأثيث كامل.
- توزيع القائمة على الأنواع وفق الجدول المعتمد؛ لا تجهيزات سكنية للأرض تلقائيًا، ولا مصعد/مطبخ للمزرعة لمجرد وجود مبنى غير موصوف.
- وجود تجهيز لا يثبت حالته الفنية أو السلامة أو الوصول الشامل. لا كشف فني أو تقييم مهني ضمن P03.

### 3.4 توزيع التجهيزات المعتمد

يعني السماح بإدخال الحقل فقط، وليس وجوده أو جعله مطلوبًا. الحقول غير المنطبقة لا تخزن false بدل «لا ينطبق».

| النوع | التجهيزات المسموحة من القائمة المعتمدة |
|---|---|
| أرض | المواقف المخصصة إن وجدت كجزء من العرض؛ خدمات الكهرباء/المياه/الصرف في مجموعتها، لا غرف أو مصاعد مفترضة |
| شقة / فيلا | العشرة كاملة، كل حقل بمعلومة صريحة مستقلة، دون توريث تجهيزات المبنى للوحدة |
| عمارة | مصعد، مواقف، تكييف مركب، مسبح، حوش، سطح خاص؛ لا مطبخ أو غرف عامل/سائق تخص وحدة واحدة بوصفها تجهيزًا لكل العمارة |
| تجاري | مصعد، مواقف، تكييف، مطبخ، مسبح، حوش، شرفة، سطح خاص عند انطباقها على المعروض؛ لا غرف نوم أو غرف عمالة منزلية افتراضية |
| مزرعة | مواقف، مسبح، حوش؛ لا تجهيزات مبنى غير موصوف من مجرد وجود مساحة بناء |
| أخرى | العشرة عند إدخالها صراحة حسب المعروض؛ وصف النوع نفسه اختياري، ولا استنتاج أو نسخها من تصنيف مخمّن |

الخدمات المعتمدة للأرض/العمارة/التجاري: كهرباء ومياه وصرف موصولة فعلًا، كل منها true/false/null. للمزرعة: مصدر ماء رئيسي (شبكة/بئر/توريد خارجي/متعدد/أخرى/لا يوجد)، وكهرباء موصولة، ووجود ري، وعدد آبار. مجهول المصدر null؛ لا نضيف «غير معلوم» كمرادف «لا يوجد». للمزرعة يبقى إجمالي البناء معلومًا أو null؛ عمر وتشطيب مبنى منفرد داخلها يحتاج نطاقًا موصوفًا لاحقًا، ولا ينسب تلقائيًا للمزرعة كلها.

### 3.5 دلالات التجاري والوحدات المعتمدة

المعتمد: `COMMERCIAL` يبقى النوع الرئيسي، مع نطاق وحدة/مبنى كامل، وتصنيف محل/مكتب/مستودع/معرض/أخرى. لا نضيف نوعًا رئيسيًا جديدًا ولا نجعله تصريح نشاط.

- النطاق والتصنيف اختياريان، لكن تقديم رقم دور أو عدد أدوار أو مساحة متخصصة مرتبطة بالنطاق يستلزم بيان النطاق المناسب في النتيجة المحفوظة بعد الدمج؛ لا يلزم إعادة إرساله كل مرة إذا كان محفوظًا ولم يتغير. تظل الطلبات العامة القديمة دون المواصفات الجديدة صالحة ما لم يوجد التعارض المعلن.
- وحدة: رقم دور، لا عدد أدوار مبنى كامل. مبنى كامل: عدد أدوار ووحدات، لا رقم دور وحدة واحد.
- إجمالي الوحدات والسكنية والتجارية حقول مستقلة اختيارية. إذا عرف الإجمالي لا يتجاوزه أي عدد جزئي أو مجموع الجزئيين؛ لا نساوي المجموع بالإجمالي إن كانت هناك وحدات أخرى أو غير مصنفة، ولا نخترع إجماليًا من بند واحد معلوم.
- عدد الوحدات لا يزيد غرف النوم، والمطبخ أو المصعد لا يثبت تجهيز كل وحدة. القيم تعبر عن نطاق العقار المعلن، لا ترثها إعلانات الوحدات تلقائيًا.

## 4. المساحات المنفصلة — التعريفات والتوافق المعتمدان

### المسار المختار: مساحات مسماة منفصلة

تعريفات عملية اعتمدها المستخدم لهذه المنصة؛ ليست أسماء API نهائية أو معايير قياس نظامية معتمدة:

| المساحة | التعريف المعتمد لهذه المنصة |
|---|---|
| قطعة الأرض | مساحة القطعة المرتبطة بالمعروض، لا نصيب أرض مفترض لكل شقة |
| صافي الوحدة | الداخل القابل للاستخدام للوحدة المعلنة، دون سماكات الجدران أو الشرفات أو المواقف أو المشترك |
| إجمالي الوحدة | المساحة المبنية للوحدة مع سماكات جدرانها، دون الشرفات المفتوحة أو المواقف أو نصيب المشترك؛ ليست مساحة بناء العمارة كلها |
| إجمالي البناء | مجموع المساحات المبنية المغلقة لأدوار العقار المعروض، شاملًا الأقبية والملاحق المغلقة، دون الأسطح/الشرفات المفتوحة أو المواقف غير المبنية |

هذه مفاهيم إعلانية لا تثبت مساحة صك أو رفع هندسي. إذا لم يكن أساس رقم مستند أو إعلان معلومًا، يستخدم «معلنة غير مصنفة» بدل نسبته لتعريف غير متحقق. لا تحويل أو نسبة معيارية بين الصافي والإجمالي، ولا اشتقاق من طول×عرض أو مساحة دور واحد. إذا قدم الصافي والإجمالي لنفس الوحدة، لا يزيد الصافي على الإجمالي. لا نفرض إجمالي البناء≤الأرض، ولا نقارن صافي شقة بقطعة أرض غير معلومة العلاقة.

المساحات الجديدة كلها بالمتر المربع، BigDecimal/precision12 scale2 والمجال0.01..9999999999.99 عند تقديمها، والطلب/الاستجابة نصوص عشرية دقيقة أو null. هذه إعادة استخدام لحد تخزين حالي، لا تقدير لحجم عقار مناسب أو حكم سوقي. قبول الأرقام القديمة الصحيحة في حقول الطلب الحالية لا يتغير.

اختار المستخدم الرئيسية صراحة من إحدى المساحات المدخلة والمنطبقة، مع مسار «معلنة غير مصنفة» إذا لم يعرف التفاصيل. تعرض الواجهة القيمة المختارة دون إعادة إدخال مكرر، ولا تختار حسب النوع أو أكبر رقم تلقائيًا. عند اختيار مصدر مسمى، يجب تطابق `area` معه بالمقارنة العددية الدقيقة لا اختلاف الأصفار النصية. اختيار مصدر بلا قيمة أو بقيمة متعارضة يرفض قبل الحفظ، ولا يختار الخادم بديلًا.

تبقى `area` القديمة محفوظة دون backfill أو تفسير من النوع أو الوصف. إنشاء قديم دون مساحات مسماة يبقى معلنًا غير مصنف؛ غياب المواصفات من التعديل القديم يحافظ على الموجود ولا يفك ربطًا حديثًا. **الربط وسياسة توافقه معتمدان ولم ينفذا.** الاستثناء المعلن: إذا عدّل عميل قديم `area` لعقار ذي ربط حديث فتعارض مع المصدر، يرفض هذا التعديل فقط بـ400 مع طلب تصحيح/فك الربط صراحة. مثال: مصدر أرض500 مع `area=600` لا يحفظ. لا فك ربط تلقائي، ولا تعديل مساحة مسماة خفية، ولا حفظ جزئي أو إبقاء مرجع غير صحيح. التعديلات القديمة المتوافقة تستمر؛ لا يدّعي التصميم قبول كل طلب قديم على سجل أغني بمواصفات حديثة.

### بديل لم يختَر — للمرجعية فقط

يبقي قيمة واحدة ويضيف معنى صريحًا اختياريًا. أبسط، لكنه لا يعرض أرض الفيلا والبناء معًا في حقول مستقلة. القيم القديمة تبقى «أساس القياس غير معلوم». البديل العام فقط يبقي حدود R3 الحالية ولا يحل المقارنة بين أسس مختلفة.

لا يتغير R3-v1 ضمن P03/P04/P05. مطابقة مساحة محددة المعنى تحتاج عقدًا واضحًا في P06 يحافظ على الطلب القديم؛ المجهول لا يحقق شرط مساحة محددة. لا اختيار مساحة تحقق الشرط بدل المساحة التي طلبها المستخدم.

## 5. قاموس القيم المعتمد

| المجموعة | التمثيل | المجال الهندسي المعتمد | معنى الصفر/null |
|---|---|---|---|
| غرف النوم/الحمامات/الصالات | JSON integer أو null |0..100 |0 يعني معلوم أنه لا يوجد؛ null مجهول |
| المواقف المخصصة | JSON integer أو null |0..1000 |0 لا موقف مخصص؛ لا يشمل موقف شارع قريب تلقائيًا |
| عدد الوحدات | JSON integer أو null |0..10000 |لا يستنتج من عدادات أو غرف، ولا يثبت صلاحية تأجير |
| عدد الأدوار فوق الأرض | JSON integer أو null |1..200، يشمل الأرضي |null مجهول؛ ليس رقم دور الوحدة |
| رقم دور الوحدة | JSON integer أو null |−10..200 |0 أرضي؛ −1 قبو أول؛ null مجهول |
| العمر التقديري وسنة التقدير | JSON integer أو null لكل منهما |العمر0..1000، السنة1900..الحالية |المجموعة كلها اختيارية؛ لا نفترض السنة أو نستخرج سنة بناء |
| عدد الآبار | JSON integer أو null |0..100 |0 معلوم عدمه؛ لا يثبت الترخيص أو جودة المياه |
| المصعد والخدمة/المياه/الكهرباء | JSON boolean أو null |true/false/null |null ليس false؛ «لا ينطبق» يتحدد بالنوع لا بقيمة false |
| نطاق/تصنيف تجاري ومصدر مساحة رئيسية | enum محدد أو null |المعاني في القسمين3.5 و4؛ الأسماء الفنية في P04 |لا قيمة افتراضية تدعي معرفة؛ مصدر null/غير محدد في الحالة المحفوظة يعني معلنة غير مصنفة، أما غياب الحقل من التعديل فيحفظه |
| وصف نوع OTHER | String أو null |حد100حرف بعد تنظيف الأطراف |لا نستخرج منه مواصفات أو نوعًا آخر آليًا |

هذه حدود وقائية معتمدة لهذه النسخة، وليست حدودًا قانونية أو خصائص سوقية. العدادات محدودة وصحيحة فتختلف عن المساحات العشرية، ولا يجوز قص الكسور أو قبول التحويل الضمني للعدادات.

الدلالات التالية مشمولة بالاعتماد النهائي:

- غرف النوم هي الغرف المنفصلة المخصصة للنوم، لا مجموع المطابخ والمجالس والصالات. صفر لا يسمى «استوديو» تلقائيًا دون تعريف متفق عليه.
- الميزانين والملحق والوحدة متعددة المستويات لا نخترع لها رقم دور. إما دعم منظم بعد القرار أو ترك الرقم غير محدد ووصفه دون ادعاء مطابقته.
- المصعد يعني أنه يخدم موضع الوحدة بحسب معلومات الأدمن، وليس ضمان وصول شامل أو مطابقة اشتراطات.
- «خدمة موصولة» تختلف عن شبكة قريبة. و«مصدر ماء قائم» يختلف عن ماء صالح أو مرخص؛ لا تقييم جودة أو قانونية ضمن الحقل.

## 6. المجهول وتغيير النوع والتحديث

اعتمد المستخدم حفظ المواصفات عند غيابها من الطلب، وتأكيد إزالة غير المنطبق أو إلغاء تغيير النوع، ورفض تغيير النوع من عميل قديم عند وجود تعارض بدل الحذف الصامت. السياسات التالية معتمدة وليست منفذة:

1. الجديد لا يأخذ صفرًا/false تلقائيًا؛ القديم يعرض «غير محدد» دون تغيير مخزونه أو إلغاء نشره.
2. أثناء إدخال الفورم، تحفظ مسودة كل نوع في الذاكرة عند التنقل، لا تمسحها لمجرد إخفاء القسم. لا حفظ دائم في المتصفح ضمن هذا القرار.
3. تغيير نوع عقار محفوظ يعرض أثره والحقول والمساحات ومصدر الرئيسية غير المنطبقة ويطلب تأكيد إزالتها أو إلغاء التغيير؛ لا تحويل غرف الشقة إلى وحدات العمارة أو أرض إلى صافي وحدة، ولا اختيار مصدر رئيسية بديل صامت.
4. الطلب غير المتوافق يرفض قبل أي حفظ جزئي. الاحتفاظ بسجل مواصفات تاريخي أو سجل تدقيق جديد خارج هذه الحزمة، ولا يفترض موجودًا.
5. غياب القسم الجديد يحافظ عليه. عند وجوده تدمج الحقول المقدمة فقط؛ غياب حقل داخله يبقي قيمته، وnull صريح للحقل يمسحه؛ `{}` بلا أثر، وnull للقسم كله يرفض400 بدل مسح جماعي ملتبس. زوج العمر يحدث/يمسح معًا؛ وقواعد المصدر والمساحة والانطباق تراجع على النتيجة النهائية قبل حفظها. لا يغير ذلك دلالة PUT للحقول القديمة. اسم القسم وشكل التخزين والترقية في P04، لا حاجة لإعادة سؤال المستخدم عن سياسة الدمج المعتمدة.
6. إذا غير عميل قديم النوع وكانت مواصفات جديدة متعارضة محفوظة، فالرفض بدل الحذف الصامت معتمد؛ يبقى تغيير نوع بلا تعارض ممكنًا. لا رفض شامل لكل الطلبات القديمة، ولا قبول تعارض على حساب سلامة القيم.
7. المسح الصريح لا يتجاوز قواعد الاتساق: مسح مساحة ما زالت مصدر الرئيسية يقتضي تصحيح المصدر صراحة ضمن الطلب نفسه، وإلا400؛ وتغيير نطاق التجاري يعامل كتغيير النوع عند وجود حقول غير منطبقة، بتأكيد إزالتها في الواجهة ومسحها صراحة في الطلب أو رفضه. لا فك ربط أو حذف تبعي صامت.

المخطط المفاهيمي فقط: `Property الحالي → مساحة معلنة + مصدر اختياري صريح → مساحات مسماة ومواصفات اختيارية منطبقة على النوع/النطاق`. غياب القسم يحفظه؛ حضوره يدمج قبل التحقق من الاتساق والانطباق؛ لا حفظ جزئي عند الخطأ. لا يحسم هذا المخطط جدولًا منفصلًا أو أعمدة أو JSONB أو أسماء حقول API.

**إغلاق P03:** اكتمل الفحص وتسجيل القرارات والجدول وخطة التوافق وأمثلة القبول. التالي P04 لاقتراح JPA/DTO ووسيلة تمييز absent عن null وعقد API وترقية المخطط وعرض أثرها للاعتماد قبل التنفيذ؛ تختبر الترقية والـround-trip على PostgreSQL معزول فقط. P05 للفورم والعرض وتأكيد تغيير النوع، وP06 لعقد احتياجات/مطابقة الأنواع المستقل. لا SQL أو تغييرات تطبيق أو اختبارات تشغيلية أو خدمات أو commit/merge/push في P03؛ تحقق التوثيق والروابط فقط.
