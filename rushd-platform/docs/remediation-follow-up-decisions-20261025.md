# قرارات الحزمة التالية — 25 أكتوبر 2026

مقترحات تنتظر اعتماد صاحب المشروع، وليست تغييرات مطبقة. لا تفعيل قاعدة أو إعادة تشغيل خدمات أو تنزيل dependencies ضمنها.

## 1. ترقية Spring/BOM — ضرورية قبل النشر

المستخدم حاليًا Boot3.3.5/Security6.3.4. أضيف حد72 بايت في التطبيق، لكنه لا يحدّث المكتبة أو يغلق كل تنبيهاتها. [إعلان CVE-2025-22228 الرسمي](https://spring.io/security/cve-2025-22228/) يثبت تأثر6.3.0–6.3.7 وأول إصلاح6.3.8؛ لا نعتمد هذا الإصدار القديم كخطة دعم2026.

[إعلان Spring الرسمي لـ3.5.16](https://spring.io/blog/2026/06/25/spring-boot-3-5-16-available-now/) يعلن نهاية الدعم المفتوح لخط3.5 ويوجه إلى4.0/4.1. اقتراحي مسار ترقية مستقل إلى **أحدث patch مستقر متاح من4.1.x**، بعد تثبيت رقمه من مستودع الإصدار الرسمي في يوم التنفيذ. بعض صفحات الوثائق المعروضة مخبأة على4.1.0؛ لم أؤكد رقم patch أحدث ولم أغيّرpom.

التوافق ليس مجرد رقم فيpom: [دليل الترحيل الرسمي](https://github.com/spring-projects/spring-boot/wiki/Spring-Boot-4.0-Migration-Guide) يوصي بالمرور على أحدث3.5 أولًا، ويشرح تغيير وحداتBoot والاختبارات وJackson3 وإزالةMockBean/SpyBean. [متطلبات4.1](https://docs.spring.io/spring-boot/system-requirements.html) تبقي Java17 حدًا أدنى، وتنتقل إلىFramework7 وServlet6.1.

الخطة بعد الاعتماد:

1. نسخة معزولة وفهرس الشجرة المحلولة؛3.5.16 مرحلة انتقال للتحقق وليست نهاية مدعومة.
2. الانتقال إلى4.1.x عبرBOM متكامل، ومراجعة Security/CSRF والاختبارات وJJWT/Hibernate، لا تثبيت إصدارات عشوائية متعارضة.
3. اعتماد ترحيل serializers/deserializers منJackson2 إلى3 مع بقاء عقود الأرقام والمواصفات. أي وحدة توافق إضافية مؤقتة تحتاج توثيقًا واعتمادًا؛ لا تبديل JSON عالمي صامت.
4. إعادة650 اختبارJava و306 واجهة ومصفوفة15,000 والمتصفح، وHibernate validate علىPG بالمخطط المراجَع. لا قبول لترقية تحتاج تعديل قاعدة المشروع تلقائيًا.
5. مراجعة التنبيهات للمجموعة الجديدة؛ ليس وعدًا بإغلاق كلCVE قبل رؤية الشجرة والنتائج.

المطلوب: اعتماد حزمة ترحيل رئيسية محددة، وليس تغيير جميعdependencies أو إعدادات النشر بلا مراجعة.

## 2. الحسابات القديمة ذات كلمات المرور الطويلة

اعتمد المستخدم رفض>72 بايت صراحة. لا يمكن استنتاج طول كلمة المرور القديمة منBCrypt hash، ولا استعادة اللاحقة التي كانت مهملة. قد تبقى البادئة72 بايت صحيحة مقابلhash قديم؛ **التحقق الجديد لا يصلح تاريخ الحسابات تلقائيًا**.

قبل الجمهور يلزم قرار استرداد موثّق يتحقق من هوية صاحب الحساب ويضع كلمة جديدة ضمن الحد. لا بريد استعادة أوendpoint أو تعديل حسابات تلقائي أضيف الآن. إذا تعذر تحديد المتأثرين، يلزم تقييم إعادة تعيين أوسع باعتماد مستقل، لا محاولة الدخول بالبادئة.

## 3. حماية التسجيل من الإساءة

اقتراح يحتاج اعتمادًا:5 محاولات تسجيل لكل عنوان فعلي/دقيقة، تشمل المدخلات المرفوضة،429 معRetry-After، سعة ذاكرة محدودة وحصة مستقلة لا تستنزف حصةlogin/refresh. يبقىgetRemoteAddr فقط، بلا ثقة فيX-Forwarded-For عشوائي، وبلا حظر دائم أو اختبار إغراق.

هذا حد عملية واحدة يعاد عند التشغيل، وليس دفاعًا موزعًا. عند النشر خلفproxy نحتاج طرفًا موثوقًا وحدودًا مشتركة وسياسة عنوان عميل واضحة. لم أضفWAF أوCAPTCHA أوخدمة أوحدًا جديدًا الآن.

## 4. مسودة الأدمن — عيب مؤكد وما زال مفتوحًا

أخطاء التحقق المحلية تحفظ المدخلات. لكن التنقل داخلReact منdashboard إلىالعقارات والعودة أعاد العنوان فارغًا. كذلك خروج الحساب من تبويب ثانٍ ثم محاولة الحفظ نقل الأول للدخول؛ بعد إعادة الدخول كانت المسودة فارغة. المصادقة منعت الحفظ، لكن عمل المستخدم غير المحفوظ ضاع.

المقترح الذي يحتاج اعتمادًا قبل توسيع حالة الحساب:

- تحذير واضح عند ترك مواصفات غير محفوظة، لا مسودة الصور وحدها.
- مسودة في **ذاكرة التبويب فقط** مرتبطة بمعرف الأدمن/العقار؛ لا إرسال تلقائي ولاlocalStorage/sessionStorage.
- عند انتهاء الجلسة لا تظهر قبل التحقق مجددًا من الأدمن نفسه، وتُمسح عند الخروج الصريح/تبديل الحساب/إغلاق التبويب. لا ضمان بقاء بعدreload أو إغلاق المتصفح في هذا الخيار.
- اختباراتReact تفاعلية ومتصفح لفشل الشبكة/401 والتنقل والتبديل. لا استبدالCSRF أو توسيع صلاحية لحفظ المسودة.

البديل: تحذير المغادرة فقط مع بقاء خسارة المسودة عند فقد الجلسة معلنة. الحفظ الدائم أو الخادمي يحتاج نطاق خصوصية ومدة احتفاظ وعقدًا مستقلًا.

## 5. إنشاء حساب المستخدم — اختيار منتج مطلوب

اختر **تسجيلًا ذاتيًا لحسابBUYER فقط** من الواجهة، أو **تزويد الحسابات إداريًا**. الأول يستلزم فورم تسجيل وحالات نجاح/تعارض/تحقق وحدود الطول وسياسة مكافحة الإساءة؛ الثاني يحتاج آلية إدارية معتمدة، لا إظهار حسابات الديمو للجمهور. لا مسار جديد نفذ الآن، ولا نشرSELLER.
