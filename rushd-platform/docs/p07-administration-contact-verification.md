# P07 — الاتصال وواتساب الإدارة

التاريخ: 19 أكتوبر 2026. الحالة: **مكتمل ومختبر محليًا، دون إرسال رسالة أو إجراء اتصال أو نشر خارجي**. اعتمد المستخدم الإعداد العام وقت البناء وACTIVE فقط، ثم أكد تصحيح الرقم المكتوب أولًا من بادئة996 إلى **+966500032165 للاتصال وواتساب معًا**. لم يصحح البرنامج البلد تلقائيًا ولم يستخدم حساب الناشر.

## التنفيذ والإعداد

- إعدادان عامان وقت البناء: `VITE_PUBLIC_CONTACT_PHONE` و`VITE_PUBLIC_WHATSAPP_PHONE`. أضيفا فارغين إلى `.env.example`، وضبطا بالرقم المعتمد في `frontend/.env.local` المتجاهل من Git، الذي لم يكن موجودًا قبل هذه الدفعة. الأرقام للنشر العام وليست أسرارًا أو بيانات مصادقة. بناء الإنتاج على جهاز آخر يحتاج ضبطهما مجددًا؛ لا اعتماد على نقل ملف محلي متجاهل.
- تظهر الإجراءات لـACTIVE فقط مع معرف صالح، ولا تظهر للمسودات أو غير المنشور أوSOLD، حتى للأدمن. إتاحة تفاصيل SOLD العامة لم تتغير.
- الاتصال برابط tel ثابت لرقم دولي صحيح الصيغة. يطبع المحلل الأرقام العربية/الفارسية، ويقبل تنسيقًا محدودًا للمسافات والأقواس والشرطات؛ يرفض النصوص والبروتوكولات والتحكم والرقم المحلي دون بلد، ولا يخمن البلد أو يثبت عمل الرقم.
- واتساب بنطاق ثابت wa.me ورقم رقمي ورسالة عربية مرمزة تحتوي معرف العقار ورابط تفاصيله العام فقط. لا عنوان عقار حر أو بريد أو هاتف ناشر أو ميزانية/احتياجات أو رموز جلسة في الرسالة. الصيغة وفق [مركز مساعدة واتساب الرسمي](https://faq.whatsapp.com/5913398998672934). الرسالة مقترحة للمستخدم، لا ترسل تلقائيًا ولا تستخدم API مدفوعًا.
- الرابط العام من أصل الموقع ومسار معرف صالح، دون query/hash أو بيانات اعتماد. يقبل HTTPS، وHTTP على loopback في التطوير فقط. الأرقام غير الآمنة من JavaScript أو معرف خارج Long الموجب لا تستخدم لتخمين رابط. غياب رقم صالح يخفي زره فقط دون fallback لبيانات حساب.
- يفتح واتساب في تبويب منفصل مع noopener/noreferrer وno-referrer. أزرار نصية ضمن الثيم الحالي، دون تحميل أصول أو برنامج خارجي أو تعديل شعار طرف ثالث.

لا endpoint أو schema أو مفتاح أو dependency أو تغيير لصلاحيات ADMIN أوcookies أوCSRF في P07.

## إصلاح مرتبط بالخصوصية ظهر في الاختبار

أظهر فحص الحالات الخاصة أن صفحة التفاصيل القديمة كانت تحتفظ بمسودة الأدمن المعروضة بعد اكتمال logout، رغم أن طلبًا جديدًا من الخادم يرفضها. لم يكن هناك زر تواصل لها، لكن بقاء العرض الخاص غير مناسب.

عولج داخل PropertyDetails فقط: نتيجة القراءة مرتبطة بمعرف العقار وهوية/دور المشاهد، وتمسح البيانات ويعاد الطلب عند تغير السياق أو انتهاء فحص الجلسة، وتمنع النتيجة المتأخرة من مشاهد سابق. حاجز العرض يمنع حتى إظهار البيانات القديمة قبل بدء effect الجديد. لا تغيير لقواعد المصادقة أو قواعد القراءة على الخادم.

أعيد السيناريو فعليًا: أدمن يفتح DRAFT، ثم logout؛ اختفى العنوان والمواصفات الخاصة، وظهرت رسالة «العقار غير موجود أو غير منشور» من طلب404. ثم فتح الزائر ACTIVE وظهر زرا التواصل كالمتوقع.

الاختبارات الجديدة تغطي الأرقام العربية/الفارسية دون تصحيح بلد، والمدخلات الخبيثة والناقصة، وغياب الإعدادين واستقلالهما، وحالات النشر، وترميز الرسالة ومحتواها المحدود، وحماية الرابط والمعرف والأصل، وloopback للتطوير فقط، ومنع استخدام بيانات الناشر.

رحلة متصفح على خادم فعلي وقاعدة PostgreSQL مؤقتة مملوكة للاختبار (نفس بيئة P06): قرئت href الفعلية ورقم الإدارة وخصائص التبويب والترميز، دون الضغط على tel أو فتح واتساب. ACTIVE أظهر الإجراءين، وSOLD/DRAFT/INACTIVE أظهرت صفر إجراءات، وDRAFT بعد الخروج404، وACTIVE متاح للزائر. راجعنا اللقطات على سطح المكتب والجوال وعرض320/390/681/1280 دون تجاوز أفقي. لقطات مؤقتة: `/tmp/rushd-p07-review/`.

غياب الإعداد واختلاف الرقمين اختبرا بوحدات الخدمة، لا بإزالة إعداد المستخدم الحقيقي لتجربة المتصفح. لا تحقق من ملكية الخط أو اتصاله أو تسجيله في واتساب، ولا اختبار تطبيق واتساب/الهاتف على أجهزة فعلية أو كل المتصفحات وقارئات الشاشة.
