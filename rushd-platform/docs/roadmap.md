# خطة عمل روافد العقارية — مراحل مرنة

تاريخ التحديث: 6 أكتوبر 2026.
هذه خطة جديدة، وليست الخطة الأصلية المفقودة. قرار صاحب المشروع: جميع أنواع العقارات الحالية، ميزانية مالية صفر، ثلاثة أيام عمل أسبوعيًا، ومدة مرنة قد تمتد إلى سنة أو أكثر. لا موعد ملزم لثلاثة شهور ولا تقدير نهائي قبل معرفة الساعات اليومية.

مصدر القرارات: [requirements.md](requirements.md). التفاصيل التقنية أدناه مقترحة للاعتماد، وليست ميزات منفذة.

## الأساس الموجود

الهوية البيج/العنابية، صلاحيات الأدمن، عرض وإضافة وتعديل العقارات، البيع والإيجار، بيانات الموقع المنظمة، ودورة المصادقة بالـcookies موجودة. لا نعيد تنفيذها؛ نراجعها ونستكمل تجهيز النشر. دعم أسماء الأنواع في النظام لا يعني اكتمال مواصفات كل نوع أو قواعد ترشيحه.

## المراحل المقترحة

| المرحلة | التركيز | شرط الخروج |
|---|---|---|
| 1. تثبيت المتطلبات والبيانات | واجهة الاحتياجات، صلاحيات الترشيح، مواصفات الأنواع، مصادر السوق، اختبار PostgreSQL | قواعد قبول وعينات بيانات واضحة، وترقيات قاعدة مختبرة |
| 2. عرض عقاري قابل للاستخدام | الصور الآمنة، مواصفات كل نوع، الاتصال والواتساب، البحث والتصفية | الأدمن يدير عروضًا فعلية، والزائر يتصفحها ويتواصل بشأنها |
| 3. الترشيح الأساسي | شروط إلزامية وتفضيلات، ترتيب حتمي، تقييم عقار يختاره المستخدم، أسباب بقوالب | ترشيح لا يتجاوز القيود، ويصرح بالتنازلات والمجهول، ويعمل دون AI |
| 4. مرجع السوق | إدارة الأدمن للمراجع، مقارنات منضبطة بحسب النوع والفترة والوحدة | فصل حكم السعر عن الملاءمة، وإظهار «بيانات غير كافية» عند غياب الدليل |
| 5. تجربة نموذج محلي | Qwen3:4b/Ollama مرشح، حزمة أدلة، قياس العربية والوقت والذاكرة، فشل آمن | قرار نموذج موثق من اختبار فعلي؛ لا تختلق المخرجات بيانات ولا تغير الحسابات |
| 6. الميزات المكملة | المفضلة، مقارنة 2–3 عقارات، اختيار الموقع والخريطة، PDF | مقارنة سليمة وتقرير متسق، ومزود موقع وتخزين ضمن الموارد المعتمدة |
| 7. تجربة عامة وإطلاق | قرار استضافة واقعي، HTTPS، صلاحيات وحدود طلبات، أداء وجوال ونسخ احتياطي | تجربة على بيئة النشر وخطة رجوع ومراقبة وبيان واضح لحدود الخدمة |

ترتيب المراحل قابل للتعديل بعد الاعتماد. يمكن عرض نسخة مفيدة بالصور والتواصل والترشيح الأساسي قبل اكتمال التفسير اللغوي والخرائط وPDF؛ تبقى الميزات الباقية ضمن النسخة المستهدفة، ولا توصف هذه النسخة الجزئية بأنها المشروع الكامل.

## تنظيم الأيام الثلاثة — اقتراح

- اليوم الأول: تاسك صغير محدد ومعايير قبوله وتنفيذ جزء أساسي منه.
- اليوم الثاني: استكمال وربط الباكند بالواجهة وتجربة حالات الخطأ.
- اليوم الثالث: اختبارات ومراجعة أمان وتوثيق وتسليم قابل للتحقق.

هذا تقسيم للعمل لا وعد بتاسك واحد في كل أسبوع. نعيد تقدير المراحل بعد أول دورتين عمل بناءً على الساعات الفعلية والنتائج. لا توجد مدة نهائية أو قائمة تاسكات مغلقة الآن.

## الأولويات والتبعيات

- جميع الأنواع مطلوبة، لكن المواصفات وقواعد الترشيح تختبر لكل نوع؛ لا تقييم عام لسعر المتر.
- محرك التصفية والترتيب قبل النموذج اللغوي؛ النموذج يشرح الحقائق ولا ينشئها.
- مرجع السوق مطلوب للحكم على السعر، لكنه لا يمنع بدء مطابقة الاحتياجات مع المواصفات.
- الحفاظ على Spring Boot كحد أمان ومصدر بيانات؛ FastAPI اختياري لخدمة Python داخلية، وليس إعادة كتابة للنظام.
- تشغيل نموذج محلي على الجهاز الحالي مرشح للتجربة فقط؛ لا نفترض استضافة AI مجانية مستقرة للزوار.
- اختبار Qwen3:4b قبل اعتماده. عند ضعف الجودة أو الموارد، يستمر الترشيح بقوالب تفسير ولا يحجب الموقع.
- اختيار مزود الخريطة وتخزين الصور والاستضافة وفحص الشروط قبل ربط خدمات أو مفاتيح. أي خدمة مدفوعة تحتاج قرارًا جديدًا.
- لا تخزين طويل لاحتياجات المستخدم ولا إرسالها إلى سحابة دون اعتماد سياسة واضحة.
- يعتمد الإطلاق على PostgreSQL وHTTPS وبيئة النشر، لا نجاح اختبارات H2 وحدها.
- كل مرحلة تقسم لاحقًا إلى تاسكات باكند وواجهة واختبار وتوثيق؛ عدد المراحل ليس عدد التاسكات المتبقية.

## الخطوة التالية بعد R1

اعتماد قواعد المطابقة للاحتياجات المشتركة مع العقارات المنشورة، وتوحيد المدينة والحي دون تغيير السجلات القديمة بصمت، ثم تنفيذ محرك الترشيح الأساسي واختبار حالات النقص وانعدام النتائج. لا ينتظر هذا العمل تنزيل نموذج أو امتلاك استضافة GPU. حقول كل نوع التفصيلية تحتاج نمذجة منفصلة.

التقدم الحالي: اعتمد صاحب المشروع نموذج أسئلة واضحًا للمسجلين فقط. اكتملت واجهة [R1 — احتياجات المستخدم](requirement-01-user-needs.md) وعقد تحقق المدخلات دون حفظ دائم، ونجحت الاختبارات وتجربة المتصفح محليًا. هذا لا يعني اكتمال المرحلة الأولى أو تنفيذ الترشيح؛ مواصفات الأنواع واختبار PostgreSQL ومراجع السوق ما زالت أعمالًا منفصلة.

## لاحقًا

طلبات اهتمام داخل الموقع ومتابعتها، توسيع المدن، وتدريب نموذج تقدير متخصص إذا توفرت بيانات وموارد وبموافقة منفصلة. العقود والمدفوعات ليست ضمن النطاق الحالي.

## تعريف الإنجاز

تحقق شروط القبول، اختبارات ناجحة، توثيق محدث، مراجعة صلاحيات وخصوصية، وتجربة حقيقية على بيئة النشر. لا تعتبر الصور أو الترشيح أو AI أو الخرائط أو PDF منفذة لأنها مذكورة في الخطة.
