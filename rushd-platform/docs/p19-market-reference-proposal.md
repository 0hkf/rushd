# P19 — مسودة عقد مراجع السوق

تحديث 10 نوفمبر 2026: اعتمد المستخدم [النطاق المحافظ ومراجعة المصدر](p19-market-source-review-20261110.md). **أغلقت P19 كحزمة قرار وفحص مصدر فقط**؛ لا تقييم سعري أو قواعد كفاية/حداثة/تصنيف نهائية. النص أدناه مسودة تاريخية، ولا يعني اعتماد جميع خياراتها. P20 لتصميم إدارة المراجع، وP21 ينتظر عينة مؤهلة واعتماد قواعد الحساب.

الحالة: **مسودة للمناقشة، غير معتمدة**. لا تتضمن أسعارًا سوقية أو مصدرًا تم التحقق من ترخيصه أو قرارًا نهائيًا بالتصنيف. لا تضيف API أو schema أو استدعاء خدمة أو scraping. تعتمد على [المتطلبات](requirements.md#5-بيانات-السوق-والتحليل--تصميم-مقترح-ينتظر-الاعتماد) و[خطة P19–P22](execution-prompts.md#p19--اعتماد-مراجع-السوق-ووحدات-المقارنة). ينتظر اعتماد المستخدم بعد تقديم عينة مصدر فعلية مسموح استخدامها ومراجعة قرارات المقارنة.

أفاد المستخدم أنه **لا يتوفر مصدر حاليًا**. يمكن إعداد التصميم وحالات القبول الاصطناعية، لكن لا يجوز عرض تحليل سوق فعلي أو اعتماد حدود نهائية توحي بصحة إحصائية قبل توفر مصدر ومراجعة ملاءمته وصلاحية استخدامه.

## 1. الهدف وما ليس هدفًا

مساعدة المستخدم لاحقًا على فهم **سعر العرض بالنسبة إلى مراجع محددة ومعلومة المصدر**، منفصلًا عن تقييم ملاءمة العقار لاحتياجاته في P17/P18. لا يعني انخفاض سعر الإعلان عن عينة صغيرة أنه فرصة أو أن العقار جيد، ولا تعد المخرجات تقييمًا مهنيًا أو ضمان ربح أو بديلًا عن التحقق الميداني. المعايير والقيم والحدود هنا مقترحات لا محركًا منفذًا.

إذا لم تتوفر عينة كافية ومتجانسة ومسموح بها، يكون الجواب «لا تتوفر بيانات كافية لتقييم السعر» مع بيان سبب النقص، لا سعر سوق مختلق ولا نتيجة إيجابية تجميلية. وجود إعلان بلا سعر أو مصدر معلوم لا يجعله دليلًا. البيانات غير المعلومة تبقى مجهولة ولا تصبح صفرًا.

## 2. ما نحتاجه من مصادر فعلية

- مثال رابط أو ملف أو مستند من مصدر يخوّل استخدام البيانات، مع معلومات الناشر وشروط إعادة العرض والتخزين والتحديث والنسب؛ إتاحة صفحة للعرض لا تكفي وحدها لإثبات حق النسخ أو النشر. لا تُعرض بيانات اتصال أو هوية شخصية دون ضرورة وسياسة معتمدة.
- وصف طبيعة الملاحظة: **سعر طلب إعلان**، أو **سعر صفقة مكتملة**، أو مرجع مجمّع؛ إعلان البيع ليس دليلًا على إتمام البيع أو سعر الصفقة. المصدر المجمّع لا يعامل تلقائيًا كملاحظات مستقلة لكل عقار.
- تاريخ رصد القيمة وتاريخ حدوث الصفقة أو نشر الإعلان إن توفر، وما إن كان تاريخ آخر تعديل معروفًا. يجب إظهار الفرق بين تاريخ الرصد وتاريخ الواقعة؛ أحدهما لا يحل تلقائيًا محل الآخر.
- نطاق البيانات المتاح ودرجة تفصيل النوع والحي والمساحة ووحدة السعر، وكيف يُعرف تكرار الإعلانات أو تعديلات السعر أو انتهاء الإعلان، وما إذا كانت الصفقات أو الأسعار المعروضة تشمل رسومًا أو ضريبة.
- بيانات وحق استخدام مكاني معقول؛ عينة اصطناعية تستخدم للاختبارات فقط وموسومة بوضوح، ولا تُقدَّم كمرجع سوقي أو تستخدم لإنتاج حكم للزوار. إذا لا توجد عينة فعلية، يمكن استكمال التصميم وبناء حالات قبول افتراضية دون تفعيل تحليل فعلي.

## 3. عقد مفاهيمي لمرجع واحد — مقترح لا schema

المسميات أدناه تصف المعلومات المطلوب بحثها، وليست أسماء DTO أو أعمدة أو حقولًا أقر المستخدم إلزامها في الإنتاج.

| المجموعة | المعلومات المقترحة والأسئلة المفتوحة |
|---|---|
| الهوية والمصدر | مرجع داخلي مستقر، اسم الناشر، دليل المصدر أو رابط آمن قابل للعرض، معرّف المصدر إن وجد، حالة الترخيص وتاريخ التحقق منه. رابط المصدر دليل فقط؛ لا يُجلب تلقائيًا من الباكند ولا يبيّن بذاته قانونية الاستخدام. |
| طبيعة الرصد | إعلان/صفقة مكتملة/مجمّع، تاريخ الرصد، تاريخ الواقعة أو نشر الإعلان، وقت آخر تحديث معلوم، حالة الصلاحية ومتى انتهت أو سحبت إن عُرفت. لا تنشأ قيمة وقت مجهولة تلقائيًا. |
| النطاق | مكة والحي المعلن، نوع العقار، البيع أو الإيجار، وفترة الإيجار. تجاري وحدة/مبنى كامل عند توفرها؛ النص غير الموحد أو النطاق المجهول لا يُحوّل إلى حقيقة بالاستنتاج. |
| السعر | قيمة موجبة دقيقة، عملة، وحدة واضحة: إجمالي بيع أو إيجار شهري أو إيجار سنوي أو قيمة لكل متر مع بيان معنى المساحة. هل يشمل السعر الضريبة/الرسوم/الأثاث أو لا أو غير معلوم؟ لا يُستنتج ذلك من المصدر. |
| المساحة | مساحة موجبة ووحدتها ومعناها الصريح عند الحاجة: أرض، صافي وحدة، إجمالي وحدة، إجمالي بناء، أو مساحة معلنة غير مصنفة. المساحة القديمة المعلنة لا تُصنف تلقائيًا؛ عدم وجود مساحة مسماة لا يُعوض بقيمة أخرى. |
| استقلالية المصدر | معرّف الملاحظة الأصلي عند السماح، أو دليل موثق على الاستقلال والتكرار أو عدم القدرة على الجزم؛ نسخ الإعلان نفسه أو تعديل سعره ليست عينات مستقلة تلقائيًا. لا نجزم بزوال التكرار عند غياب المعرف. |
| إدارة الأدلة | من أدخل المرجع، وقت إدخاله وتعديله، سبب إيقافه أو استبعاده، نسخة المرجع/قواعد المقارنة والتاريخ اللازم لتفسير النتيجة. تصميم التدقيق والصلاحيات والاحتفاظ يحدد لاحقًا، ولا يعني هذا حفظ بيانات المستخدم. |

السعر الحالي للعقار `price` في [Property.java](../backend/src/main/java/com/rushd/entity/Property.java) دقيق بحدود العمود الحالي، و`area` موجودة بمعنى معلن؛ توجد معانٍ مسماة في [PropertyNeedsAreaBasis.java](../backend/src/main/java/com/rushd/dto/PropertyNeedsAreaBasis.java). هذه حقائق عن النظام الحالي، وليست حدودًا نهائية مقترحة لمرجع السوق. يناقش P20 نطاق القيم والدقة و`null` والترقية والتوافق قبل التنفيذ؛ لا تغير قيم العقار أو أعمدته هنا.

## 4. أهلية المقارنة — سياسة محافظة مقترحة

1. يُفصل سعر الطلب عن سعر الصفقة؛ لا ندمجهما في عينة واحدة أو نعرضهما كنوع واحد. المرجع المجمّع له سياسة منفصلة بعد معرفة منهجه وحجم عينته.
2. تكون المراجع من النطاق الجغرافي المعتمد ونفس نوع العقار ونوع العرض والوحدة، وفترة الإيجار عند انطباقها، ومعنى المساحة إذا كانت المقارنة تعتمد عليها. النطاق التجاري وحدة/مبنى كامل لا يخلط. لا مقارنة إيجار شهري بإيجار سنوي أو سعر بيع تلقائيًا.
3. الحي المجهول أو المختلف والسعر أو الفترة أو نوع الملاحظة أو معنى المساحة المجهول لا يُستنتج؛ يقترح استبعاده عندما يكون ذلك الحقل لازمًا للمقارنة. تحديد الحالات التي يمكن فيها المقارنة بإجمالي السعر دون مساحة، أو بالمتر بدل الإجمالي، يحتاج قرارًا بحسب النوع والمصدر.
4. يحفظ سبب استبعاد كل مرجع: اختلاف الوحدة أو النوع أو نطاق الموقع، قدم المرجع، التكرار أو غياب معلومة لازمة، مع التفريق بين عدم المعرفة والمخالفة. لا تُستثنى قيمة شاذة لمجرد أنها لا تناسب النتيجة؛ تعريف الشذوذ وقيوده يحتاج اعتمادًا.
5. تطبق حداثة العينة وعدد الملاحظات المستقلة وتاريخ الواقعة حسب قواعد مُعلنة بعد مراجعة عينات المصدر. لا تحدد هذه المسودة حدًا رقميًا موثوقًا بلا دليل. إذا حدث تعارض أو تعذر إثبات الاستقلال، يعرض أثره ولا يخمن.
6. المبالغ والمساحات تقارن بحساب عشري دقيق. تدرَس سياسة تقريب صريحة للنتائج المشتقة في P21 ولا يُقرب سعر العرض المخزن. أي تحويل عملة أو فترة أو مساحة يحتاج عقدًا ومصدر تحويل مؤرخًا واعتمادًا مستقلًا؛ الافتراض الحالي عدم التحويل.

## 5. الثقة والتغطية — لا نسبة دقة مختلقة

**مقترح:** يُعرض وصف أدلة قابل للفهم بدل «ثقة 85%» أو احتمال الربح: نوع المرجع، عدد الملاحظات التي أمكن إثبات استقلالها، تاريخ أقدم وأحدث واقعة مع تاريخ الرصد، المدينة والحي والنوع والفترة والوحدة، ما نُقص أو استُبعد وأسبابه، واسم المصدر ونسخة قواعد التحليل. لا يوصف عدد الملاحظات بأنه نسبة ثقة إحصائية، ولا يعني المصدر الرسمي بالضرورة أن كل ملاحظة ممثلة للعقار المختار.

يمكن إضافة تسمية وصفية لاحقًا، لكنها تحتاج تعريفًا معلنًا وقابلًا للاختبار لما تقيسه وحدودها، ولا تكون ضمانًا لصحة التقدير. إذا لم تثبت أهلية العينة وفق السياسة المعتمدة، تعرض «بيانات غير كافية» مع الحقائق المتاحة دون إظهار حكم ضمن/أعلى/أقل يوحي بالكفاية.

## 6. قرارات مطلوبة قبل P20 وP21

1. **المصادر:** ما المثال الفعلي أو الملف المسموح به؟ هل نبدأ بصفقات مكتملة أو أسعار إعلانات أو نفصل القسمين؟ كيف نحصل على حق التخزين وعرض المصدر ومراجعة تحديثه؟
2. **التجانس:** هل نعتمد المقارنة المحافظة المذكورة، مع فصل الحي ونوع العقار والبيع/فترة الإيجار ونوع المرجع ومعنى المساحة؟ ما تفاصيل التجاري والمساحة التي يسمح المصدر بإثباتها؟
3. **الحداثة والكفاية:** ما أقصى عمر لكل نوع مرجع، وأقل عدد ملاحظات مستقلة، وكيف نتعامل مع الإعلان المكرر أو القديم أو القيم المتطرفة؟ لا تختار المسودة أرقامًا أو تدعي دليلًا إحصائيًا لها؛ أي حدود ستحتاج مراجعة المستخدم ومعايرة مع المصدر الفعلي.
4. **المؤشر وطريقة الإظهار:** هل نكتفي بالوسيط والفارق عن مرجع مؤهل، أم نضيف تسميات أقل/ضمن/أعلى؟ في الخيار الثاني، ما الحدود وتفسيرها؟ لا ينفذ حساب أو تصنيف قبل اعتماد السياسة المناسبة وطريقة التقريب.
5. **وصف الثقة:** هل نكتفي بعرض الحقائق وعدد العينات وحداثتها ونوعها دون نسبة ثقة أو حكم مصنف لجودتها؟ وإن اختيرت تسمية، ما تعريفها وحدودها وما الذي لا تدعيه؟
6. **تغير المصادر:** هل تحفظ نتائج التحليل بصورة مؤقتة أم مؤرخة قابلة للاسترجاع؟ ما سياسة تصحيح المرجع أو سحبه وتأثيره على لقطة سابقة؟ لا نفترض تخزينًا دائمًا لاحتياجات المستخدم من هذا السؤال.

بعد اعتماد العقد فقط تعرض P20 تصميم API/schema وتفويض الأدمن والترقية وسياسة البيانات القديمة قبل التنفيذ، ثم يعتمد P21 طريقة الحساب والتصنيف. لا تتغير نتيجة P17/P18 أو ترتيب R3 أو تُرسل الاحتياجات إلى AI ضمن P19.

## 7. حالات قبول واختبار مستقبلية

هذه حالات مصطنعة بلا أسعار واقعية، لا دليل سوق:

- إعلان وصفقة أو إيجار شهري وسنوي، أو صافي وحدة ومساحة بناء: لا تخلط حسب السياسة المعتمدة، وتعرض أسباب الاستبعاد.
- نوع أو حي أو مصدر أو تاريخ واقعة أو وحدة مجهولة: لا تُملأ قيم افتراضية؛ ينقص الدليل أو تُستبعد الملاحظة بحسب العقد المعتمد.
- ملاحظة مكررة أو إعلان تغير سعره أو مصدر مجمّع غير مثبت عدد أفراده: لا يزيد عدد العينات المستقلة تلقائيًا.
- عينة أقدم من الحد المعتمد أو أصغر من الحد الأدنى، أو لم يثبت حق استخدامها: لا ينتج حكم سعري؛ تعرض أسباب نقص البيانات دون اختلاق.
- عينات مؤهلة عند الحد، وأسعار/مساحات دقيقة ومقادير قصوى وحالات الصفر والسالب والتقريب والتعادل: حساب حتمي قابل لإعادة الإنتاج مع وحدة واضحة.
- تصحيح أو سحب مرجع أو تغير العقار: النتيجة القديمة تبقى موضحة كلقطة إن اعتمد حفظها، وإعادة التحليل تقرأ نسخ الحقائق المعتمدة؛ لا ادعاء تحديث لحظي.
- حالات 401 و403 وCSRF وADMIN وبيانات قديمة وPostgreSQL وRTL وأمان رابط المصدر مطلوبة عند بناء API والواجهة لاحقًا. لا وصول تلقائي للشبكة أو تنفيذ HTML من المصدر.
