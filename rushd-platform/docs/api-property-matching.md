# عقد المطابقة — R3-v1 وP06-v2

تاريخ التحديث: 19 أكتوبر 2026. يبقى الطلب القديم وقواعد matching-v1 مدعومين، وأضيفت [امتدادات P06 المعتمدة](p06-type-matching-verification.md) مع تحقق PostgreSQL المعزول. لا تغييرات schema أو مصادقة أوAI.

`POST /api/property-needs/matches?page=0&size=10` يبحث في العروض المنشورة وفق احتياجات R1، ويرتب كل مجموعة المطابقة ضمن حد المعالجة قبل تقسيم الصفحات. لا AI ولا تقييم سعر أو استثمار ولا حفظ دائم.

## الطلب والوصول

- الجسم نفس [عقد R1](api-property-needs.md)، بنفس الحدود وقواعد enum والحقول غير المدعومة والتوافق بين البيع والإيجار. لا يلزم استدعاء `/validate` أولًا.
- access cookie لحساب مسجل و`X-XSRF-TOKEN` صالح مطلوبان. كل الأدوار تحصل على `ACTIVE` فقط؛ صلاحية الأدمن لا توسع مجموعة المطابقة.
- `page` عدد صحيح من صفر، و`size` عدد صحيح من 1 إلى 20 (الافتراضي 10). معلمات أخرى أو مكررة ترفض؛ لا اختيار sort غير موثق.
- الطلب لا يقبل معرف مستخدم أو قائمة عقارات يفرضها العميل أو أوزانًا أو درجات أو حالة نشر. لا يكشف بيانات الناشر.
- `/api/property-needs/validate` يشارك إضافات P06 الاختيارية؛ التصفح العام وCRUD لم يتغيرا في هذه الحزمة.

مثال:

```json
{
  "listingType": "SALE",
  "type": "LAND",
  "maxBudget": "1500000.50",
  "district": "حي النوارية",
  "districtRequirement": "PREFERRED",
  "minArea": "350",
  "maxArea": "750",
  "areaRequirement": "PREFERRED",
  "searchGoal": "INVESTMENT"
}
```

## الاستجابة

مثال مختصر للحقول القديمة لنتيجة واحدة؛ البيانات ليست من قاعدة المشروع الفعلية. إضافات الاستجابة الحالية موثقة في قسم P06 أدناه حتى للطلب القديم:

```json
{
  "needs": {
    "listingType": "SALE",
    "rentalPeriod": null,
    "type": "LAND",
    "maxBudget": "1500000.50",
    "district": "حي النوارية",
    "districtRequirement": "PREFERRED",
    "minArea": "350",
    "maxArea": "750",
    "areaRequirement": "PREFERRED",
    "searchGoal": "INVESTMENT",
    "city": "مكة المكرمة",
    "currency": "SAR",
    "areaUnit": "SQUARE_METRE"
  },
  "content": [
    {
      "id": 1,
      "title": "أرض توضيحية",
      "type": "LAND",
      "listingType": "SALE",
      "rentalPeriod": null,
      "city": "مكة",
      "district": "النوارية",
      "price": "950000.50",
      "area": "500.00",
      "createdAt": "2026-10-13T10:00:00",
      "preferredMatchedCount": 2,
      "preferredCount": 2,
      "districtMatch": "MATCHED",
      "areaMatch": "MATCHED",
      "reasons": [
        "السعر المعلن ضمن الحد الأعلى للميزانية، وليس تقديراً لإجمالي التكاليف أو قيمة السوق.",
        "الحي يحقق تفضيلك.",
        "معيار المساحة المسجلة في الإعلان يحقق تفضيلك."
      ]
    }
  ],
  "page": 0,
  "size": 10,
  "totalElements": 1,
  "totalPages": 1,
  "rulesVersion": "matching-v1",
  "sort": "PREFERENCES_THEN_NEWEST"
}
```

`reasons` رسائل واقعية بقوالب وقد تتضمن أسباب الأهلية والتنبيه إلى حدود هدف البحث؛ لا تعتمد الواجهة على نص الرسالة كرمز برمجي. كل من السعر والمساحة سلسلة عشرية دقيقة، والمساحة المجهولة null. لا تحولها إلى `Number` لحسابات المطابقة أو العرض. عدد التفضيلات ليس نسبة أو تقييمًا.

حالات `districtMatch/areaMatch`:

| القيمة | المعنى |
|---|---|
| `MATCHED` | البيانات تحقق المعيار المطلوب |
| `MISMATCHED` | البيانات تخالف التفضيل المرن؛ لا يرجع مخالف لشرط إلزامي |
| `UNKNOWN` | بيانات المعيار غير معروفة أو غير واضحة؛ لا تحتسب تطابقًا |
| `NOT_REQUESTED` | لم يطلب المستخدم هذا المعيار؛ لا شرط أو نقطة |

السعر هو سعر الإعلان ضمن الفترة نفسها وSAR حسب نموذج المنصة، لا إجمالي تكاليف أو قيمة سوقية. المساحة هي المسجلة للنوع نفسه، لا تأكيد للصافي أو البناء. هدف البحث لا يرشح بحسب `purpose` ولا يثبت صلاحية استثمار أو استعمال قانوني.

## القواعد وحد المعالجة

- أهلية دائمة: `ACTIVE` ومكة ونفس النوع ونوع العرض وفترة الإيجار، وسعر موجب لا يتجاوز الميزانية. `REQUIRED` للحي أو المساحة يستبعد المخالف والمجهول؛ `PREFERRED` لا يستبعد.
- مقارنة المدينة بالمخزون تقبل `مكة` و`مكة المكرمة` و`Makkah` فقط بعد توحيد whitespace وحالة الأحرف اللاتينية. مدخل R1 للمدينة لم يتوسع.
- الحي من `district` فقط؛ توحيد whitespace وبادئة `حي` المنفصلة مرة واحدة، دون fuzzy أو تبديل حروف أو استنتاج من حقول Google. لا تعدل القيم المخزنة أو الظاهرة.
- الترتيب: عدد التفضيلات المتحققة تنازليًا، ثم تاريخ الإضافة تنازليًا (المجهول أخيرًا)، ثم المعرف تنازليًا. نطاق المساحة تفضيل واحد، والشرط الإلزامي لا يمنح نقطة.
- المجموعة الأولية محدودة بـ1000 مرشح **قبل** مقارنة الموقع، وقد تشمل مدنًا أخرى. الاستعلام يحمل 1001 كحد أقصى لكشف تجاوز الحد؛ عند التجاوز لا يعيد أي عينة، بل `422`. تضييق الميزانية أو المساحة الإلزامية قد يقلله؛ شرط الحي لا يقلل هذه المجموعة الأولية في النسخة الحالية.
- الترتيب يحسب على كامل مجموعة المطابقة المتاحة للطلب، لا أول صفحة من التصفح. لا snapshot دائم بين الطلبات؛ تغيير المخزون قد يغير عدد النتائج والصفحات.

## الأخطاء والفراغ

| HTTP | الحالة |
|---|---|
| `200` | نتيجة كاملة ضمن حد المعالجة؛ بما فيها انعدام التطابق |
| `400` | جسم أو معلمات أو حدود غير صالحة، أو معلمات إضافية/مكررة |
| `401` | لا مصادقة صالحة، مع رمز CSRF صالح |
| `403` | رمز CSRF غائب/غير صالح |
| `422` | البحث يتجاوز حد المرشحين الأوليين؛ ليس «لا نتائج» |

لا مطابقات: `content=[]`, `totalElements=0`, `totalPages=0`. صفحة بعد النهاية مع مطابقات موجودة: `content=[]` مع أعداد موجبة، ويجب أن تعرض الواجهة عودة لصفحة صالحة لا رسالة عدم وجود عقارات. عدم التطابق لا يوسع الميزانية أو الشروط تلقائيًا.

الواجهة تستخدم نسخة ثابتة من الاحتياجات عند تغيير الصفحات؛ أي تعديل أو مسح أو خروج أو تغير حساب يلغي الطلب المعلق ويمسح النتائج. الردود المتأخرة لا تستعيد معلومات قديمة.

لا أعمدة أو ترقية قاعدة بيانات أو dependencies أو مفاتيح جديدة لهذا العقد. اختبار PostgreSQL وجاهزية النشر لا يستنتجان من نجاح H2؛ النتائج الفعلية توثق في R2/R3.

## امتدادات P06 — matching-v2

حقول الطلب الإضافية areaBasis وcommercialScope وspecificationCriteria وقواعد الشكل والانطباق في [عقد الاحتياجات](api-property-needs.md). العمر المؤرخ والوصف الحر مستبعدان، ونطاق التجاري شرط هيكلي لا نقطة تفضيل. العدد الأقصى التقني28 معيار مواصفات، إضافة إلى الحي ومدى المساحة؛ الفعلي يتحدد بالمنطبق والمطلوب.

كل REQUIRED يستبعد المخالف والمجهول، وكل PREFERRED بوزن واحد ولا يستبعد. نطاق العداد كله معيار واحد. false لا يحققها null، و0 ليس مجهولًا، والقوائم مساواة لا ترتيب جودة ضمني. الترتيب بعد عدد التفضيلات: الأحدث ثم المعرف. لا نسبة أو درجة100 أوتقييم سوق.

الشروط الجديدة الإلزامية والمساحة المسماة والنطاق المختار تدخل SQL قبل حد1000. تبقى المقارنة النصية للموقع بعد المجموعة الأولية؛ لا ترتيب عينة أو تجاوز الحد أو تخفيف شرط. الطلبات بلا استخدام جديد تبقى matching-v1، ويصبح matching-v2 عند اختيار معنى مساحة مسمى أو نطاق تجاري أو معيار مواصفات.

إضافات الاستجابة:

- داخل needs: areaBasis افتراضيADVERTISED، وcommercialScope=null عند الغياب، وspecificationCriteria={} عند الغياب.
- داخل كل نتيجة: areaBasis كاسم معنى المساحة، وmatchedArea كنص عشري دقيق أو null، وspecificationMatches كقائمة أدلة للمعايير المطلوبة فقط. تبقى area مساحة الإعلان القديمة ولا يعاد تعريفها لتساوي معيارًا آخر.
- الدليل مثل `{ "field": "hasElevator", "requested": { "value": false, "requirement": "PREFERRED" }, "actual": null, "outcome": "UNKNOWN" }`. العدادات المطلوبة تعيد min/max بدلvalue، والقوائم اسمها النصي. لا بيانات حسابات أو ناشر في الأدلة.
- الحقول القديمة باقية، لكن عميلًا خارجيًا بمخطط JSON مغلق قد يحتاج تحديثًا. الواجهة حدثت العدد المتغير للتفضيلات والملخص والأدلة ونسخة الاحتياجات العميقة وإلغاء الردود القديمة.

الطلب القديم الصحيح لا يصبح غير صالح لمجرد الإضافة، ولا تستنتج مساحة مسماة للسجل القديم. معيار مساحة مسماة مفقود: UNKNOWN عند التفضيل واستبعاد عند الإلزامي، لا fallback إلى area. [نتائج 484 اختبارًا على PG/H2 و158 للواجهة والمتصفح](p06-type-matching-verification.md).
# إضافة P10

تحتوي كل نتيجة على `primaryImage` descriptor أوnull اختيارية للعرض لاحقًا. القراءة bulk للصفحة النهائية فقط؛ لا تغيير للشروط أو أوزان التفضيلات أو ترتيب matching-v1/v2. [عقد الصور](api-property-images.md). عند التعطيل لا تقرأ metadata الصور.
