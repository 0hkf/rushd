# P06 — المطابقة بحسب مواصفات النوع

التاريخ: 19 أكتوبر 2026. الحالة: **مكتمل ضمن التنفيذ والاختبار المعزول، وليس تفعيلًا لقاعدة المشروع**. اعتمد المستخدم [النطاق والعقد التفصيلي](p06-p07-execution-proposal.md) قبل التعديل. لا تعديل schema أو مصادقة أو نشر أو بيانات فعلية، ولا AI أو حكم سعري.

## التنفيذ

- أضيف `areaBasis` لاختيار معنى واحد للمساحة، و`commercialScope` كشرط هيكلي اختياري، و`specificationCriteria` اختياري بحد أقصى 28 مفتاحًا من قاموس P04 نفسه: 10 عدادات و13 قيمة منطقية و5 قوائم. العمر المؤرخ والوصف الحر ومصدر الرئيسية خارج المعايير.
- العدادات نطاقات صحيحة شاملة ضمن حدود P03؛ boolean والقوائم قيم صريحة بأنواع صحيحة، والأهمية REQUIRED/PREFERRED مطلوبة لكل معيار. قارئ موضعي يرفض الأنواع الخاطئة والمجهول والمكرر، دون ObjectMapper عام. التحقق قبل PropertyRepository، بما فيه انطباق النوع والنطاق ومعنى المساحة.
- غياب الإضافات أو خلو المعايير يبقي الطلب القديم على matching-v1؛ الاستخدام الجديد matching-v2. الحقول القديمة باقية. إضافات الاستجابة قد تتطلب تحديث عميل خارجي ذي مخطط مغلق؛ مستهلكو المشروع واختباراتهم حدثوا معًا.
- كل REQUIRED يرشح في SQL قبل حد1000، ثم تعاد مراجعة الأدلة في الخدمة. المجهول لا يحقق الإلزامي أو التفضيل، وfalse/0 معلومات معلومة. كل تفضيل بوزن واحد؛ المدى كله معيار واحد، ثم الأحدث والمعرف. لا تحميل غير محدود أو ترتيب عينة؛ يبقى422 عند اتساع المرشحين الأوليين، قبل تطبيع المدينة والحي كما في السابق.
- المساحة المسماة لا تستعاض من مساحة أخرى أو من `area`. تبقى `area` مساحة الإعلان القديمة، وتضاف `matchedArea` للقيمة التي قورنت بالفعل؛ كلها نصوص دقيقة. تظهر المواصفة المطلوبة والقيمة المسجلة والأهمية وMATCHED/MISMATCHED/UNKNOWN في `specificationMatches` دون معلومات حسابات.
- حدث نموذج الاحتياجات والملخص والنتائج. لا اشتراط جديد افتراضي. تغيير السياق المؤثر يطلب تأكيد إزالة المعايير غير المنطبقة، مع مسودات ذاكرة عند العودة؛ مدى مساحة غير منطبق يمسح مع معناه دون إعادة تفسير. كل تعديل يلغي النتائج والطلب السابق.
- نسخة احتياجات الصفحات أصبحت عميقة ومستقلة ومجمدة تكراريًا، لمنع تغير معيار متداخل بعد إرسال البحث. لا localStorage أو حفظ احتياجات في DB.
- أصلح الفحص البصري انقسام السعر الطويل: رموز الأرقام لا تلتف، وخانات البطاقة تصبح عمودًا واحدًا عند ضيق محتواها. بقي الثيم والخط وRTL دون تغيير.

## المتصفح

استخدم خادم Spring Boot وReact/Vite فعليين مع PostgreSQL tmpfs جديد مملوك للاختبار على loopback. أعيد استخدام مشغّل المعاينة المؤقت السابق بملكية جديدة؛ لا بيانات المشروع. أنشئ23عقار fixture عبر API العادي بعد تسجيل دخول حساب اختبار؛ تعطي الشقة المجهولة وسجلاتDRAFT/SOLD/INACTIVE حالات استبعاد حقيقية.

- بحث صافي120–180.50 مع غرف≥3 وتفضيل مصعد وتشطيب كامل أعاد12نتيجة على صفحتين، والشقة الأقدم المحققة للتفضيلين جاءت أولًا، لا الأحدث المجهولة بياناته. ظهر السعر9007199254740993.01 دقيقًا، ومساحة الإعلان900 منفصلة عن الصافي150.25.
- الصفحة الثانية عرضت الاختلاف والمجهول دون احتسابهما؛ جعل المصعد إلزاميًا أبقى الشقة المعروفة فقط. طلب false إلزاميًا اختار العقار المسجل «لا»، لا المجهول.
- تفعيل معيار مواقف0 جُرب لكل الأنواع السبعة ولكلا نطاقي التجاري؛ النتائج بالنوع والنطاق فقط. طلب قديم دون الإضافات أعادmatching-v1. شرط غير محقق أعاد صفرًا دون تخفيف.
- صيغة1e99999 رفضت في الواجهة وبقيت كما أدخلت. جُرب إلغاء وتأكيد تغيير السياق، ومسح نطاق المساحة غير المنطبق، ثم استعادة المسودة وقيمها العربية/الفارسية عند العودة.
- أوقف خادم الاختبار مؤقتًا بـSIGSTOP لطلب معلق؛ تعديل المعيار ألغاه وأزال النتائج. بعد SIGCONT لم تظهر نتيجة قديمة ولا رسالة فشل متأخرة. هذا لا يوقف خادم المستخدم.
- على320/390/681/1280px: عرض الصفحة مساوي للـviewport، ولا رقم خارج خلية المواصفات، والرقم الحساس في سطر واحد. روجعت لقطات `/tmp/rushd-p06-review/` بعد تصحيح الالتفاف. لا اختبار لكل جهاز أو قارئ شاشة أو أحمال إنتاج.
